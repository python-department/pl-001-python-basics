# Инструкция raise и повторное возбуждение исключений

> **Главная мысль.** Инструкция `raise` **возбуждает исключение** явно: Python
> прерывает выполнение текущего кода и начинает искать обработчик, так же как
> при исключении, возбужденном самим интерпретатором. Исключение можно
> возбудить как с передачей сообщения (`raise ValueError("message")`), так и с
> указанием только типа (`raise ValueError`, объект исключения будет создан
> автоматически).
> Внутри блока `except` инструкция `raise` **без аргументов** возбуждает перехваченное
> исключение повторно (**re-raise**): так можно выполнить частичную обработку
> (например, записать сообщение) и передать исключение дальше, не потеряв ни
> тип, ни трассировку.

---

## 1. Явное возбуждение исключения

До сих пор исключения возбуждались интерпретатором при выполнении операций
(например, `ZeroDivisionError` при делении на ноль) и при вызове встроенных
функций и объектов (например, `ValueError` в `int("abc")`). При необходимости
разработчик может возбудить исключение явно, например, когда данные не
соответствуют ожидаемым условиям. Инструкция `raise` допустима в любом месте
кода, в том числе вне функций; в примере ниже она находится в функции:

```python
def calculate_square_root(number: float) -> float:
    if number < 0:
        raise ValueError("number must not be negative")

    return number ** 0.5


print(calculate_square_root(16))  # 4.0
print(calculate_square_root(-4))  # ValueError: number must not be negative
```

Инструкция `raise` выполняет три действия:

1. создает объект исключения (если указан только тип, создает исключение без
   аргументов);
2. записывает в него трассировку;
3. прерывает выполнение текущего кода и запускает поиск обработчика.

Инструкции, следующие за `raise` в том же блоке, не выполняются. Функция
`calculate_square_root` либо возвращает корректный результат, либо возбуждает
исключение.

Возбужденное явно исключение можно перехватить так же, как и любое другое:

```python
try:
    calculate_square_root(-4)

except ValueError as error:
    print(f"Error: {error}")  # Error: number must not be negative
```

## 2. Исключение с сообщением и без него

Инструкция `raise` принимает либо **созданное исключение** (тип, вызванный с
аргументами, как функция), либо **только тип**:

```python
raise ValueError("number must not be negative")  # исключение с сообщением
raise ValueError                                 # только тип: сообщение пустое
```

Во втором случае Python сам создает исключение, вызывая тип без аргументов
(`ValueError()`). Эквивалентные записи:

```python
raise ValueError
raise ValueError()
```

Аргументы, переданные при создании исключения, сохраняются в атрибуте `args`,
а сообщение об ошибке составляется из них:

```python
try:
    raise ValueError("first", 42)

except ValueError as error:
    print(error.args)  # ('first', 42)
    print(error)       # ('first', 42)
```

На практике почти всегда передается одно **информативное сообщение**: что
именно некорректно и какое значение вызвало ошибку. В идеале сообщение об
ошибке указывает на причину так, чтобы пользователю было понятно, как
исправить ошибку.

```python
def set_age(age: int) -> int:
    if age < 0:
        raise ValueError(f"age must not be negative, got {age}")

    return age
```

## 3. Выбор типа исключения

В Python есть много встроенных исключений, которые покрывают большое количество
ситуаций. Часто этого набора достаточно, и следует выбирать **готовое
исключение, тип которого соответствует причине ошибки**. Примеры:

| Ситуация | Тип |
|---|---|
| Значение подходящего типа, но недопустимое (отрицательный возраст, пустая строка) | `ValueError` |
| Аргумент неподходящего типа | `TypeError` |
| Запрошенного ключа или индекса нет в коллекции | `KeyError`, `IndexError` |

```python
def repeat_text(text: str, times: int) -> str:
    if not isinstance(times, int):
        raise TypeError(f"times must be int, got {type(times).__name__}")

    if times < 0:
        raise ValueError(f"times must not be negative, got {times}")

    return text * times
```

В специфических ситуациях при решении узкоспециальных задач можно определять
собственные типы исключений. Этот механизм рассматривается позже, после
знакомства с классами; до тех пор следует использовать встроенные типы с
информативным сообщением.

## 4. Повторное возбуждение: raise без аргументов

Иногда обработчик может выполнить только **часть** работы: например, записать
сообщение об ошибке, но принять решение о ее обработке должен вызывающий код.
В этом случае исключение необходимо передать дальше, не изменяя.

Внутри блока `except` инструкция `raise` **без аргументов** возбуждает то же
самое перехваченное исключение:

```python
def load_age(raw_age: str) -> int:
    try:
        return int(raw_age)

    except ValueError:
        print("Failed to parse age")
        raise


try:
    load_age("abc")

except ValueError as error:
    print(f"Caught outside: {error}")
```

Вывод:

```
Failed to parse age
Caught outside: invalid literal for int() with base 10: 'abc'
```

Функция сообщила о проблеме, а затем передала то же исключение вызывающему
коду, где оно было перехвачено окончательно.

### Чем raise отличается от raise error

Можно возбудить перехваченное исключение и явно, по имени:

```python
except ValueError as error:
    raise error
```

Результат внешне похож, но различия существенны:

- голый `raise` сохраняет исходную трассировку без изменений: в ней
  указана строка, в которой исключение возникло изначально;
- `raise error` добавляет в трассировку еще одну запись — строку, в которой
  выполнен этот `raise`; трассировка становится длиннее и менее наглядной;
- `raise` лаконичнее и не требует имени `as error`.

Поэтому для повторного возбуждения того же исключения используется голый `raise`.

### Типичные применения

Повторное возбуждение применяется, когда обработчик должен:

- записать сообщение в журнал или вывести диагностику, но не подавлять ошибку;
- освободить ресурсы или откатить изменения, а затем передать ошибку выше;
- обработать исключение только при определенном значении его атрибута, а в
  остальных случаях возбудить его дальше. Различить такие случаи отдельными
  блоками `except` нельзя, так как тип исключения у них один и тот же:

```python
import errno

try:
    process_data()

except OSError as error:
    if error.errno != errno.ENOSPC:
        raise  # остальные ошибки ввода-вывода обрабатывает вызывающий код

    print("Disk is full, clearing cache")
```

Здесь `OSError` с кодом `ENOSPC` (на диске нет свободного места) обрабатывается
на месте, а `OSError` с любым другим кодом передается вызывающему коду.

## 5. raise вне блока except

Голый `raise` имеет смысл только **при обработке исключения**: ему необходимо
исключение, которое можно возбудить повторно. Если обрабатываемого исключения
нет, Python возбуждает `RuntimeError`:

```python
raise  # RuntimeError: No active exception to reraise
```

Голый `raise` следует записывать непосредственно в теле блока `except`.

---

## 6. Возбуждение нового исключения в блоке except

Блок `except` может не передавать пойманное исключение дальше, а возбудить
**другое** исключение, более подходящее по смыслу для вызывающего кода:

```python
def load_age(raw_age: str) -> int:
    try:
        return int(raw_age)

    except ValueError:
        raise RuntimeError("failed to load age")


try:
    load_age("abc")

except RuntimeError as error:
    print(f"Caught: {error}")
```

Вывод:

```
Caught: failed to load age
```

Вызывающий код получил `RuntimeError` с собственным сообщением, а не `ValueError`
из `int`.

Исходное исключение при этом не теряется: Python связывает его с новым в
**цепочку исключений**. Подробнее — в следующем конспекте.

## Вывод

- `raise` возбуждает исключение явно. Можно указывать исключение с сообщением
  (`raise ValueError("message")`) или только тип (`raise ValueError`).
- Сообщение должно быть информативным: указывать, что именно некорректно и
  какое значение привело к ошибке, а в идеале подсказывать, как исправить
  ошибку.
- В Python есть готовые встроенные исключения для большого количества ситуаций
  (`ValueError` для недопустимого значения, `TypeError` для неподходящего
  типа и другие). Для специфических ситуаций можно определять собственные типы
  исключений.
- `raise` без аргументов внутри `except` повторно возбуждает перехваченное
  исключение с сохранением типа и трассировки. Так выполняется частичная
  обработка (запись в журнал, освобождение ресурсов) с передачей исключения
  вызывающему коду.
- Голый `raise` предпочтительнее, чем `raise error`; вне обработки исключения
  он приводит к `RuntimeError`.
- Из блока `except` можно возбудить новое исключение; связь с исходным
  описывается цепочками исключений.
