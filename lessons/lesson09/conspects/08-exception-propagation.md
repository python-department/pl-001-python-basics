# Механизм распространения исключений

> **Главная мысль.** Возбужденное исключение не обязано обрабатываться там, где
> возникло. Если в выполняемом блоке кода подходящего `except` нет, его
> выполнение **прерывается**, а исключение **передается во внешний блок**, то
> есть туда, откуда этот блок был запущен (вызван или импортирован). Там поиск
> обработчика повторяется. Так исключение **поднимается по стеку вызовов**
> (раскрутка стека, stack unwinding) до первого подходящего `except`. Если
> обработчик не найден даже на самом внешнем уровне (в главном модуле),
> программа завершается и выводится трассировка. Это справедливо для любого
> кода: тела функции или метода, тела класса, кода уровня модуля. Благодаря
> этому промежуточные уровни не обязаны передавать ошибки вручную, а обработка
> выполняется там, где известно, что делать.

---

## 1. Стек вызовов

Код в Python выполняется блоками: тело функции или метода, тело класса,
код уровня модуля. Каждый выполняющийся блок получает собственный **кадр
выполнения (frame)**. Когда один блок кода запускает другой (вызов функции,
создание класса, импорт модуля), интерпретатор хранит **стек вызовов (call
stack)**: список активных кадров, в котором последний запущенный находится
сверху.

Для наглядности ниже используются функции, но механизм одинаков для любых
блоков кода.

```python
def read_age(raw_age: str) -> int:
    return int(raw_age)


def build_profile(raw_age: str) -> dict[str, int]:
    return {"age": read_age(raw_age)}


def main() -> None:
    profile = build_profile("abc")
    print(profile)


main()
```

Стек на момент выполнения `int(raw_age)` (сверху вниз — от последнего вызова
к первому):

```
read_age("abc")        <- здесь возникает ValueError
build_profile("abc")
main()
<module>
```

---

## 2. Распространение исключения вверх

Ни `read_age`, ни `build_profile`, ни `main` не содержат `try-except`. Поэтому
исключение проходит через все уровни:

1. `int("abc")` возбуждает `ValueError`. Выполнение тела `read_age`
   прекращается: оператор `return` не выполняется, значение не возвращается.
2. В `read_age` обработчика нет. Исключение передается в точку вызова —
   в тело `build_profile`. Его выполнение также прекращается.
3. В `build_profile` обработчика нет. Исключение передается в тело `main`.
   Строка `print(profile)` не выполняется.
4. В `main` обработчика нет. Исключение передается на уровень модуля.
5. На уровне модуля обработчика нет, поэтому программа завершается, а
   интерпретатор выводит трассировку.

Результат:

```
Traceback (most recent call last):
  File "example.py", line 14, in <module>
    main()
  File "example.py", line 10, in main
    profile = build_profile("abc")
  File "example.py", line 6, in build_profile
    return {"age": read_age(raw_age)}
  File "example.py", line 2, in read_age
    return int(raw_age)
ValueError: invalid literal for int() with base 10: 'abc'
```

**Трассировка читается сверху вниз как путь вызовов**: сначала самый внешний
уровень, в конце — блок кода, в котором возникло исключение. Последняя строка
содержит тип и сообщение. Для поиска причины обычно смотрят на последние
записи трассировки.

Важное следствие: **оставшиеся операторы не выполняются на каждом уровне,
через который проходит исключение**. В примере это `return` в `read_age`,
оставшаяся часть `build_profile` (после вызова `read_age`) и строка
`print(profile)` в `main`. Выполнение продолжится только после
обработчика, если он найден.

## 3. Перехват на промежуточном уровне

Если на каком-либо уровне есть подходящий `except`, распространение
останавливается:

```python
def read_age(raw_age: str) -> int:
    return int(raw_age)


def build_profile(raw_age: str) -> dict[str, int]:
    try:
        return {"age": read_age(raw_age)}

    except ValueError:
        return {"age": 0}


def main() -> None:
    profile = build_profile("abc")
    print(profile)  # {'age': 0}


main()
```

Исключение возникло в `read_age`, прошло в `build_profile`, где было
перехвачено. После выполнения `except` функция `build_profile` завершается
обычным образом и возвращает значение, а `main` продолжает работу и получает
результат без признаков ошибки. Код `main` об исключении не информирован.

Таким образом, обработка находится на том уровне, на котором **достаточно
информации** для принятия решения: `read_age` не знает, что делать с
некорректным возрастом, а `build_profile` знает, что нужно подставить значение по
умолчанию.

## 4. Поиск обработчика идет от внутреннего уровня к внешнему

Если подходящие обработчики есть на нескольких уровнях, сработает **ближайший
к месту возникновения исключения**, то есть самый внутренний:

```python
def read_age(raw_age: str) -> int:
    try:
        return int(raw_age)

    except ValueError:
        print("read_age: handled")
        return 0


def main() -> None:
    try:
        print(read_age("abc"))

    except ValueError:
        print("main: handled")  # не выполняется


main()
```

Вывод:

```
read_age: handled
0
```

Исключение перехвачено в `read_age`, поэтому до `main` оно не дошло.

Если обработчик указан, но его тип не подходит, он не срабатывает, и исключение
передается во внешний блок кода (в точку вызова), где поиск продолжается:

```python
def read_age(raw_age: str) -> int:
    try:
        return int(raw_age)

    except KeyError:  # не подходит: возникло ValueError
        print("read_age: handled")
        return 0


def main() -> None:
    try:
        print(read_age("abc"))

    except ValueError:
        print("main: handled")


main()  # main: handled
```

## 5. Исключение в обработчике и повторное возбуждение

Исключение продолжает распространяться и в том случае, когда обработчик
сам его возбуждает: голый `raise` или `raise ... from ...` внутри `except`
передает исключение (то же или новое) во внешний блок кода:

```python
def read_age(raw_age: str) -> int:
    try:
        return int(raw_age)

    except ValueError:
        print("read_age: logging error")
        raise


def main() -> None:
    try:
        read_age("abc")

    except ValueError:
        print("main: handled")


main()
```

Вывод:

```
read_age: logging error
main: handled
```

Если же внутри блока `except` возникает **новое** исключение, не связанное с
исходным обработчиком, то оно заменяет исходное и тоже поднимается вверх
(с цепочкой, см. предыдущий конспект).

## 6. Исключения, не принадлежащие ни одному обработчику

Если в стеке нет подходящего `except`, исключение достигает уровня модуля и
**завершает программу**. Это нормальная и часто желательная ситуация: если
программа не знает, как исправить ошибку, лучше остановиться и показать
трассировку, чем продолжать работу с некорректным состоянием.

```python
def main() -> None:
    print("Start")
    int("abc")
    print("Finish")  # не выполняется


main()
print("After main")  # не выполняется
```

```
Start
Traceback (most recent call last):
  ...
ValueError: invalid literal for int() with base 10: 'abc'
```

Другие строки после `main()` не выполняются: программа остановлена.

Это справедливо не только для исключений, возникших внутри функций.
Исключение, возникшее непосредственно в коде уровня модуля, ведет себя так же.
Стек состоит из единственного кадра `<module>`, и если в нем нет обработчика,
программа завершается:

```python
print("Start")
int("abc")
print("Finish")  # не выполняется
```

Так же исключение поднимается из тела класса и из метода: тело класса
выполняется при определении класса, а метод — при его вызове, и в обоих
случаях исключение передается во внешний блок кода, откуда было запущено их
выполнение.

---

## 7. Принципы выбора уровня обработки

- **Обрабатывайте исключение там, где известно, что делать.** Если текущий
  уровень не может предложить осмысленную реакцию, пусть исключение
  поднимется выше.
- **Не перехватывайте исключения без необходимости.** Лишние `try-except` на
  промежуточных уровнях скрывают ошибки и усложняют код.
- **Верхний уровень программы** (точка входа) — подходящее место для общего
  обработчика: он может вывести понятное сообщение, записать трассировку в
  журнал и завершить программу с кодом ошибки.
- Промежуточный уровень, который может лишь частично обработать ошибку
  (записать в журнал, освободить ресурс), перехватывает исключение и возбуждает
  его повторно (`raise`).

---

## Вывод

- Если в выполняемом блоке кода (тело функции или метода, тело класса, код
  уровня модуля) нет подходящего `except`, его выполнение прерывается, а
  исключение передается во внешний блок, откуда он был запущен. Так происходит
  до обнаружения первого подходящего обработчика (**раскрутка стека**).
- Оставшиеся операторы на каждом уровне, через который проходит исключение, не
  выполняются.
- Сработает самый внутренний подходящий обработчик. Если обработчик не
  подходит по типу, исключение передается во внешний блок кода, и поиск
  продолжается там.
- Если обработчика нет нигде, программа завершается и выводится трассировка;
  она читается сверху вниз как путь вызовов, последняя строка — тип и
  сообщение исключения.
- Исключение обрабатывают на том уровне, где достаточно информации для
  принятия решения; промежуточные уровни не обязаны передавать ошибки вручную.
