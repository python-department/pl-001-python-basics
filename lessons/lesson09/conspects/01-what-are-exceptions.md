# Исключения: что это и зачем они нужны

> **Главная мысль.** **Исключение (exception)** — это специальный объект,
> который сообщает об **исключительной ситуации**: событии, из-за которого
> выполнение кода не может продолжаться обычным образом (деление на ноль,
> обращение к несуществующему ключу, отсутствующий файл). Когда такая ситуация
> возникает, Python создает объект исключения и **возбуждает (raise)** его:
> обычный порядок выполнения прерывается, а объект передается вверх по стеку
> вызовов до тех пор, пока не будет **обработан**. Если обработчика нет,
> программа завершается с сообщением об ошибке. Благодаря этому ошибка не
> остается незамеченной, а код, обнаруживший проблему, отделен от кода,
> который решает, что с ней делать.

---

## 1. Исключительная ситуация и объект исключения

Рассмотрим функцию, которая вычисляет среднее значение:

```python
def calculate_average(numbers: list[int]) -> float:
    return sum(numbers) / len(numbers)


print(calculate_average([4, 8, 15]))  # 9.0
print(calculate_average([]))
```

Вызов с пустым списком приводит к делению на ноль, для которого нет
осмысленного результата. Программа останавливается и выводит **трассировку
(traceback)** — отчет о цепочке вызовов, которая привела к исключению:

```
Traceback (most recent call last):
  File "example.py", line 6, in <module>
    print(calculate_average([]))
          ~~~~~~~~~~~~~~~~~^^^^
  File "example.py", line 2, in calculate_average
    return sum(numbers) / len(numbers)
           ~~~~~~~~~~~~~^~~~~~~~~~~~~~
ZeroDivisionError: division by zero
```

**Трассировка** — это текстовое представление состояния стека вызовов в
момент возбуждения исключения. Она состоит из трех частей:

1. **Заголовок** `Traceback (most recent call last)` — указывает порядок
   записей: от самого раннего вызова к самому позднему (`most recent call
   last` — «последний вызов в конце»).
2. **Записи о вызовах (кадры стека).** Каждая запись содержит имя файла,
   номер строки, имя функции (`<module>` — код верхнего уровня, не входящий в
   функцию) и саму строку кода, выполнение которой привело к исключению.
   Символы `~` и `^` под строкой кода указывают на фрагмент, вызвавший
   исключение.
3. **Последняя строка** — тип исключения с сообщением об ошибке.

В примере первая запись показывает, что вызов `calculate_average([])`
выполнялся в строке 6 модуля. Вторая запись показывает, что исключение
возникло в строке 2 внутри `calculate_average`, при вычислении
`sum(numbers) / len(numbers)`.

Трассировку удобно читать **снизу вверх**: последняя строка сообщает, что
произошло, ближайшая к ней запись — где это произошло, а предыдущие записи —
через какие вызовы программа к этому месту пришла.

Последняя строка трассировки состоит из двух частей: **типа исключения**
(`ZeroDivisionError`) и **сообщения об ошибке** (`division by zero`) —
текста, который поясняет причину исключения. Оба значения берутся из объекта
исключения: при делении на ноль интерпретатор создал исключение типа
`ZeroDivisionError` и передал в него это сообщение.

Исключение — **объект**, как и любое другое значение в Python. У него есть тип,
а также атрибуты, в которых хранятся данные о произошедшем:

```python
try:
    calculate_average([])

except ZeroDivisionError as error:
    print(type(error))             # <class 'ZeroDivisionError'>
    print(error)                   # division by zero
    print(error.args)              # ('division by zero',)
    print(error.__traceback__)     # <traceback object at 0x...>
```

- `type(error)` — возвращает тип исключения;
- `error.args` — кортеж аргументов, с которыми было создано исключение
  (обычно это сообщение);
- `error.__traceback__` — объект трассировки: те же записи о вызовах, через
  которые исключение прошло, в виде объекта, доступного из кода.

Конструкция `try ... except` разбирается в отдельных конспектах. Пока важно,
что исключение можно перехватить и получить доступ к объекту.

## 2. Зачем нужны исключения

Рассмотрим, как сообщали бы об ошибке без исключений. Функция должна вернуть
число, но входные данные могут быть некорректными. Один из вариантов — вернуть
специальное значение:

```python
def parse_age(raw_age: str) -> int:
    if not raw_age.isdigit():
        return -1

    return int(raw_age)


age = parse_age("abc")
print(age + 1)  # 0 -- ошибка осталась незамеченной
```

У этого подхода есть недостатки:

- **Признак ошибки совпадает по типу с результатом.** Значение `-1` — тоже
  `int`. Вызывающий код должен помнить, что `-1` означает ошибку, и проверять
  это после каждого вызова.
- **Ошибку легко проигнорировать.** Если проверка не написана, программа
  продолжает работать с неверным значением, и сбой проявится позже и в другом
  месте, что усложняет поиск причины.
- **Нет информации о причине.** Одно значение `-1` не говорит, что именно
  пошло не так.
- **Каждый уровень вызовов обязан передавать признак ошибки дальше**, иначе он
  будет потерян.

Исключения решают эти проблемы:

```python
def parse_age(raw_age: str) -> int:
    return int(raw_age)


age = parse_age("abc")  # ValueError: invalid literal for int() ...
print(age + 1)          # не выполнится
```

- **Ошибку нельзя не заметить.** Если исключение не обработано, программа
  останавливается, а не продолжает работу с неверными данными.
- **Результат функции всегда корректен.** Возвращаемое значение не смешивается
  с признаком ошибки: функция либо вернула результат, либо возбудила
  исключение.
- **Исключение несет информацию.** Тип, сообщение и трассировка показывают,
  что и где произошло не так.
- **Исключение распространяется автоматически.** Промежуточные функции не
  обязаны передавать его вручную (см. конспект о механизме распространения
  исключений).
- **Обнаружение и обработка разделены.** Код, обнаруживший проблему, не
  обязан знать, как на нее реагировать: решение принимает тот уровень
  программы, у которого достаточно информации.

## 3. Исключения и синтаксические ошибки

Не следует путать исключения с **синтаксическими ошибками (syntax errors)**:

```python
print("Hello"
```

```
SyntaxError: '(' was never closed
```

Синтаксическая ошибка обнаруживается на этапе компиляции, до выполнения
программы, поэтому обработать ее внутри самой программы нельзя. Исключения
возникают **во время выполнения (runtime)**, когда код синтаксически верен,
но операция не может быть выполнена.

## 4. Жизненный цикл исключения

Жизненный цикл исключения состоит из нескольких этапов:

1. **Возникновение.** Интерпретатор или код программы обнаруживает
   исключительную ситуацию.
2. **Создание объекта.** Создается объект исключения, в который записывается
   тип, сообщение и текущее состояние стека вызовов.
3. **Возбуждение (raise) созданного исключения.** Созданный объект
   исключения передается в программу, и нормальное выполнение прерывается:
   инструкции, следующие за местом возбуждения, не выполняются.
4. **Распространение.** Python ищет обработчик, начиная с места возбуждения
   и поднимаясь вверх по стеку вызовов: сначала в текущем коде, затем в
   вызывающем и так далее.
5. **Обработка или завершение.** Если обработчик найден, выполняется его код и
   программа продолжается. Если нет — программа завершается, а интерпретатор
   выводит трассировку.

## Вывод

- **Исключение** — объект, сообщающий об исключительной ситуации, в которой
  код не может продолжать выполнение обычным образом.
- Исключение имеет тип, сообщение об ошибке и трассировку. Тип указывает на
  причину исключения (например, `ZeroDivisionError` — деление на ноль),
  сообщение уточняет детали, трассировка показывает, где оно возникло.
- Возбужденное исключение прерывает обычный порядок выполнения и
  распространяется вверх по стеку вызовов, пока не будет обработано. Если
  обработчика нет, программа завершается с трассировкой.
- В отличие от специальных возвращаемых значений, исключение невозможно
  случайно проигнорировать, оно не смешивается с результатом функции и несет
  информацию о причине.
- Исключения возникают во время выполнения и отличаются от синтаксических
  ошибок, которые обнаруживаются до запуска программы.
