# Конструкция try-finally

> **Главная мысль.** Блок `finally` выполняется **при любом исходе** блока
> `try`: после нормального завершения, после исключения (перехваченного или
> нет), а также при выходе из блока через `return`, `break` или `continue`.
> Поэтому `finally` предназначен для **безусловных завершающих действий** —
> прежде всего для освобождения ресурсов: закрытия файла, сетевого
> соединения. Для файлов, открытых через `open`, вызов `close()` в
> `finally` гарантирует, что файл будет закрыт, даже если при чтении или записи
> возникла ошибка. Блок `finally` допустим без `except`: исключение при этом не
> перехватывается, но завершающие действия все равно выполняются.

---

## 1. Синтаксис и порядок выполнения

Некоторые действия необходимо выполнить независимо от того, успешно ли
завершилась операция: закрыть файл, разорвать сетевое соединение.
Размещение такого кода после блока `try` ненадежно. Если исключение не
перехвачено ни одним `except`, выполнение программы прерывается, и строки после
конструкции не выполняются. То же происходит, если из `try` выполнен `return`.
Дублировать завершающий код в каждом `except` и в конце `try` неудобно и
приводит к ошибкам при изменении программы.

Для таких случаев в конструкцию `try` добавляется блок `finally`. Он
записывается последним и выполняется **при любом исходе** блока `try`: после
успешного завершения, после исключения и при выходе из блока через `return`,
`break` или `continue`.

Общий вид:

```python
try:
    # основной код, при выполнении которого может возникнуть исключение
    ...

finally:
    # завершающие действия, выполняются всегда
    ...
```

Блок `finally` можно использовать **как с `except`, так и без него**. Блок
`try` обязан иметь хотя бы один из них (см. конспект о `try-except`). Если
`except` отсутствует, исключение не перехватывается: блок `finally`
выполняется, после чего исключение продолжает распространяться.

В следующем примере функция принимает режим работы. В режиме `"ok"` блок `try`
завершается без ошибок, в режиме `"error"` в нем возбуждается исключение, а
блок `finally` в обоих случаях выводит сообщение:

```python
def run(mode: str) -> None:
    try:
        print("try: start")

        if mode == "error":
            raise ValueError("something went wrong")

        print("try: end")

    finally:
        print("finally: cleanup")


run("ok")
```

При вызове `run("ok")` выполняются оба блока, `finally` — после `try`:

```
try: start
try: end
finally: cleanup
```

Вызов `run("error")`:

```python
run("error")
```

Исключение возникает после первого `print`, поэтому остаток `try` (строка
`try: end`) пропускается:

```
try: start
finally: cleanup
Traceback (most recent call last):
  ...
ValueError: something went wrong
```

Во втором случае исключение не перехвачено, но блок `finally` успел
выполниться **до** того, как исключение продолжило подниматься по стеку
вызовов и привело к завершению программы.

## 2. finally при выходе из блока

Блок `finally` выполняется и тогда, когда управление покидает `try` через
`return`, `break` или `continue`:

```python
def get_value() -> int:
    try:
        return 1

    finally:
        print("cleanup")


print(get_value())
```

```
cleanup
1
```

Возвращаемое значение уже вычислено, но функция завершится только после
выполнения `finally`. Аналогично в цикле:

```python
for number in range(3):
    try:
        if number == 1:
            continue

        print(f"body {number}")

    finally:
        print(f"finally {number}")
```

```
body 0
finally 0
finally 1
body 2
finally 2
```

Итоговый порядок действий для всех исходов блока `try`:

| Исход блока `try` | Что происходит |
|---|---|
| Завершился без исключений | выполняется `finally`, затем код после конструкции |
| Возникло исключение, и оно перехвачено `except` | выполняется `except`, затем `finally`, затем код после конструкции |
| Возникло исключение, которое не перехвачено | выполняется `finally`, затем исключение продолжает распространяться |
| Выход через `return`, `break` или `continue` | выполняется `finally`, затем выход происходит |

## 3. Освобождение ресурсов: файлы и open

**Ресурс** — объект, который программа получает у операционной системы или
внешней службы в ограниченном количестве и после использования должна вернуть:
открытый файл, сетевое соединение. Возвратом называется
**освобождение** ресурса. Если ресурс не освобожден, возникают проблемы:

- количество ресурсов каждого вида ограничено; при исчерпании лимита новый
  ресурс получить не удастся;
- данные, записанные через ресурс, могут остаться в буфере и не попасть
  по назначению, пока ресурс не освобожден;
- ресурс может остаться занятым и недоступным для других программ (например,
  файл, открытый одной программой, в Windows нельзя удалить или переименовать
  из другой).

Наиболее наглядный пример ресурса — файл. Для работы с файлами в Python
используется встроенная функция `open`; подробно она рассматривается позже. В
примерах ниже достаточно знать, что `open("data.txt", "w")` открывает файл для
записи и возвращает файловый объект, а его метод `close()` закрывает файл,
освобождая ресурс и сбрасывая буфер на диск.

Простой вызов `file.close()` в конце кода ненадежен:

```python
file = open("data.txt", "w")
file.write("first line\n")
number = int("abc")  # ValueError
file.write("second line\n")
file.close()         # не выполнится: файл останется открытым
```

Функция `int("abc")` возбуждает `ValueError`, и выполнение программы
прерывается на этой строке. Вызов `file.close()` в конце не выполняется, поэтому
файл остается открытым: ресурс не освобожден. Это называется **утечкой
ресурса**. Данные из буфера могут не попасть на диск, а файл остается занятым
до завершения программы. Если такой код выполняется многократно (например, в
цикле или в функции, которая вызывается часто), число открытых файлов растет до
исчерпания лимита.

Решение — поместить закрытие в `finally`, который выполняется независимо от
того, возникла ошибка или нет:

```python
file = open("data.txt", "w")

try:
    file.write("first line\n")
    number = int("abc")  # ValueError
    file.write("second line\n")

finally:
    file.close()  # выполнится в любом случае
    print(f"File closed: {file.closed}")
```

```
File closed: True
Traceback (most recent call last):
  ...
ValueError: invalid literal for int() with base 10: 'abc'
```

Файл закрыт, хотя исключение прервало запись. Атрибут `file.closed` позволяет
убедиться в этом.

### Вызов open располагается до try

Обратите внимание: в примере выше `open` вызывается **до** блока `try`, а не
внутри него. Это принципиально. Рассмотрим ошибочный вариант:

```python
def read_file(path: str) -> str:
    try:
        file = open(path)
        return file.read()

    finally:
        file.close()


read_file("missing.txt")
```

Если файла нет, `open` возбуждает `FileNotFoundError`, и переменная `file` не
получает значения. Затем выполняется `finally`, в котором `file.close()`
обращается к несуществующему имени и возбуждает `UnboundLocalError`. Это новое
исключение возникает при обработке исходного, поэтому оно **маскирует**
настоящую причину (исходная `FileNotFoundError` остается лишь в цепочке
`__context__`).

Правильная структура: ресурс **захватывается до `try`**, а освобождается в
`finally`. Если захват не удался, то и освобождать нечего:

```python
def read_file(path: str) -> str:
    file = open(path)

    try:
        return file.read()

    finally:
        file.close()
```

Если `open` возбудит исключение, оно сразу распространится вверх, а `finally` не
выполнится: он не нужен, так как файл не был открыт.

Общий шаблон:

```python
resource = acquire()  # захват ресурса; при неудаче освобождать нечего

try:
    use(resource)     # использование

finally:
    release(resource)  # освобождение выполняется всегда
```

## 4. try-except-finally: обработка и освобождение вместе

`finally` можно сочетать с `except`. Они решают разные задачи: `except`
**реагирует на ошибку**, `finally` **выполняет завершающие действия**
независимо от наличия ошибки.

В следующем примере из первой строки файла читается число. Если строка не
является числом, `int` возбуждает `ValueError`: `except` обрабатывает его и
задает значение по умолчанию, а `finally` закрывает файл:

```python
file = open("data.txt")

try:
    first_line = file.readline()
    value = int(first_line)

except ValueError:
    print("First line is not a number")
    value = 0

finally:
    file.close()
```

Файл закрывается в обоих случаях: и когда преобразование выполнено успешно, и
когда возникло `ValueError`, обработанное в `except`. Порядок выполнения при
ошибке: сначала `except`, затем `finally`.

Вызов `open` по-прежнему находится до `try` (см. раздел 3). Поэтому
исключение при открытии, например `FileNotFoundError`, в этом примере не
обрабатывается. Чтобы обработать и его, открытие файла помещается в отдельную
конструкцию `try-except`, а чтение и закрытие остаются в `try-finally`:

```python
def read_first_line(path: str) -> str:
    try:
        file = open(path)

    except FileNotFoundError:
        return ""

    try:
        return file.readline()

    finally:
        file.close()
```

Если файла нет, функция возвращает пустую строку, и до второго `try` выполнение
не доходит: закрывать нечего. Если файл открыт, то `finally` гарантирует его
закрытие.

Полная форма конструкции: `try` → `except` → `else` → `finally`.

## 5. Особенности finally

### Исключение внутри finally

Если исключение возникает в самом `finally`, оно заменяет исходное (исходное
сохраняется в `__context__`):

```python
try:
    raise ValueError("original")

finally:
    raise RuntimeError("from finally")  # RuntimeError, ValueError в цепочке
```

Поэтому код в `finally` должен быть простым и надежным.

### return в finally

Инструкция `return` внутри `finally` имеет приоритет над всем, что происходило в
`try`. Она **отменяет** возбужденное исключение:

```python
def get_result() -> str:
    try:
        raise ValueError("lost")

    finally:
        return "from finally"  # исключение потеряно


print(get_result())  # from finally
```

Она также заменяет значение, которое возвращал `return` в блоке `try`:

```python
def get_number() -> int:
    try:
        return 1

    finally:
        return 2  # значение 1 потеряно


print(get_number())  # 2
```

В обоих случаях результат `try` теряется без следа, поэтому такая запись
считается ошибкой стиля. Начиная с Python 3.14 интерпретатор выдает
предупреждение `SyntaxWarning: 'return' in a 'finally' block`.
**Не используйте `return`, `break` и `continue` в `finally`.**

### Когда finally не выполняется

`finally` не выполнится, если процесс завершен принудительно: аварийное
завершение интерпретатора, вызов `os._exit()`, остановка процесса
операционной системой. В обычных ситуациях, включая `sys.exit()` и
`KeyboardInterrupt`, блок `finally` выполняется.

## Вывод

- Блок `finally` выполняется **всегда**: при нормальном завершении `try`, при
  исключении (перехваченном или нет), при `return`, `break` и `continue`.
- `finally` допустим без `except`; тогда исключение не перехватывается, но
  завершающие действия выполняются до его дальнейшего распространения.
- `finally` используется для **безусловного освобождения ресурсов**. Для файла
  `file.close()` помещается в `finally`, чтобы файл закрывался даже при ошибке
  чтения или записи.
- Ресурс необходимо **захватывать до `try`**: если `open` находится внутри
  `try` и завершается ошибкой, то `finally` обратится к необъявленной
  переменной и замаскирует исходное исключение.
- Исключение внутри `finally` заменяет исходное; `return` в `finally`
  отменяет исключение. Код в `finally` должен быть простым, без `return`.
