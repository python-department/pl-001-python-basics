# Конструкция try-except

> **Главная мысль.** Конструкция `try ... except` позволяет **перехватить
> исключение** и обработать его, не допуская аварийного завершения программы.
> В блок `try` помещается код, который может возбудить исключение, в блок
> `except` — код его обработки. Если в `try` исключение не возникло, `except`
> пропускается. Если возникло, оставшаяся часть `try` не выполняется, а
> управление переходит к подходящему `except`. Блок `try` **обязан** иметь
> `except` или `finally`. Писать `except` без указания типа исключения
> опасно: такой обработчик перехватывает все, в том числе остановку программы
> пользователем и скрытые ошибки в коде.

---

## 1. Синтаксис и порядок выполнения

Если исключение возникло и нигде не перехвачено, Python прекращает выполнение
программы и выводит трассировку. Для ошибки в логике кода это оправданно: ее
нужно исправить. Но многие исключения вызваны не дефектом кода, а внешними
условиями: пользователь ввел строку вместо числа (`ValueError`), файл не
существует (`FileNotFoundError`), в данных нет ожидаемого ключа (`KeyError`).
Такие ситуации ожидаемы, и для них можно заранее определить реакцию: запросить
ввод повторно, подставить значение по умолчанию, сообщить о проблеме.

Конструкция `try ... except` позволяет реализовать такую обработку. В блок
`try` помещается код, в котором исключение возможно, в блок `except` — код,
который выполняется при возникновении исключения указанного типа. После
обработки выполнение программы продолжается вместо аварийного завершения.

Общий вид конструкции:

```python
try:
    # код, который может возбудить исключение
    ...

except ExceptionType:
    # код обработки исключения типа ExceptionType
    ...
```

Здесь `ExceptionType` — имя класса исключения, которое необходимо обработать
(например, `ValueError` или `KeyError`).

Пример: преобразование введенной строки в число.

```python
raw_age = "abc"

try:
    age = int(raw_age)
    print(f"Age: {age}")

except ValueError:
    print(f"Invalid age: {raw_age!r}")

print("Program continues")
```

Вывод:

```
Invalid age: 'abc'
Program continues
```

Порядок выполнения:

1. Выполняется блок `try` строка за строкой.
2. Если исключение **не возникло**, блок `except` пропускается, а выполнение
   продолжается с первой строки, следующей за блоком `except`.
3. Если исключение **возникло**, выполнение блока `try` немедленно
   прекращается: строки после места возникновения не выполняются (в примере
   `print(f"Age: {age}")` не вызывается).
4. Python сравнивает тип исключения с типом, указанным в `except`. Если
   тип возникшего исключения совпадает с указанным в `except` или входит в
   него (см. конспект об иерархии исключений), выполняется блок `except`,
   после чего выполнение программы продолжается с первой строки, следующей за
   блоком `except` (в примере выше — с `print("Program continues")`).
5. Если тип не подходит, исключение не перехвачено и продолжает
   распространяться вверх по стеку вызовов.

Исключение, не совпавшее по типу с `except`, не обрабатывается:

```python
try:
    result = 10 / 0

except ValueError:
    print("Invalid value")

# ZeroDivisionError: division by zero
```

Обработчик `except ValueError` не подходит, поэтому `ZeroDivisionError`
завершает программу.

## 2. Доступ к объекту исключения

При возникновении исключения Python создает объект исключения. Он хранит
сведения об ошибке: тип и текстовое сообщение с описанием причины. Для
обработки может потребоваться эта информация: например, вывести сообщение
пользователю, записать его в журнал или выбрать реакцию в зависимости от
причины ошибки.

Чтобы получить доступ к объекту исключения внутри обработчика, его связывают с
переменной в заголовке `except` с помощью ключевого слова `as`:

```python
try:
    # код, который может возбудить исключение
    ...

except ExceptionType as error:
    # переменная error ссылается на объект возникшего исключения
    ...
```

Здесь `error` — имя переменной (может быть любым корректным именем).

Пример: вывод типа и сообщения исключения.

```python
try:
    int("abc")

except ValueError as error:
    print(f"Error type: {type(error).__name__}")
    print(f"Error message: {error}")
```

Вывод:

```
Error type: ValueError
Error message: invalid literal for int() with base 10: 'abc'
```

Переменная доступна **только внутри блока `except`**. После его завершения
Python автоматически удаляет имя (чтобы не удерживать ссылки на трассировку и
избежать утечек памяти):

```python
try:
    int("abc")

except ValueError as error:
    pass

print(error)  # NameError: name 'error' is not defined
```

Если значение нужно после блока, его необходимо присвоить другой переменной
внутри `except`.

## 3. Блок except обязателен

Блок `try` не может существовать сам по себе. Конструкция обязана содержать хотя
бы один `except` или блок `finally` (он рассматривается в отдельном конспекте):

```python
try:
    age = int("42")

print(age)
```

```
SyntaxError: expected 'except' or 'finally' block
```

Это синтаксическая ошибка: код даже не начнет выполняться. Блок `try` без
обработчика не имеет смысла, так как неясно, что делать с возникшим
исключением.

## 4. Опасность except без указания исключения

Python допускает запись `except` без типа исключения (так называемый
**голый except, bare except**):

```python
try:
    age = int(raw_age)

except:
    print("Something went wrong")
```

Такой обработчик перехватывает **любое** исключение, включая типы, которые
входят в `BaseException`, но не входят в `Exception`. Это приводит к нескольким
проблемам.

### Проблема 1. Невозможно остановить программу

Исключения `KeyboardInterrupt` (нажатие `Ctrl+C`) и `SystemExit` (вызов
`sys.exit()`) тоже будут перехвачены:

```python
while True:
    try:
        command = input("Enter a command: ")

    except:
        print("Something went wrong")
```

Нажатие `Ctrl+C` не остановит такую программу: исключение `KeyboardInterrupt`
будет перехвачено и проигнорировано, а цикл продолжится. Остановить программу
получится только принудительным завершением процесса.

### Проблема 2. Скрываются ошибки в коде

Опечатка в имени переменной внутри `try` приводит к `NameError`, но голый
`except` сообщит о ней так же, как и о реальной проблеме с данными:

```python
raw_age = "42"

try:
    age = int(raw_ge)  # опечатка: raw_ge вместо raw_age

except:
    print("Invalid age")  # выведено, хотя значение raw_age корректно
```

Программа сообщает о некорректном возрасте, хотя причина — ошибка в коде.
Такие ошибки трудно обнаружить, поскольку трассировка не выводится.

### Проблема 3. Неизвестно, что произошло

В голом `except` нет доступа к объекту исключения, поэтому нельзя ни узнать
причину, ни записать ее в журнал.

### Как поступать

Всегда указывайте **конкретный тип** исключения, которое ожидается и для
которого известно, как его обработать:

```python
try:
    age = int(raw_age)

except ValueError:
    print("Invalid age")
```

Если необходимо перехватить любые ошибки прикладного кода (например, чтобы
записать сообщение в журнал на верхнем уровне программы), используйте
`except Exception`. Такой обработчик не перехватывает `KeyboardInterrupt`,
`SystemExit` и `GeneratorExit`, так как эти типы не входят в `Exception`.

```python
try:
    process_data()

except Exception as error:
    print(f"Unexpected error: {error}")
```

Но и `except Exception` следует применять осторожно: такой обработчик скрывает
ошибки программиста так же, как и голый `except`, если после перехвата ничего
не происходит. Перехватить `Exception` и **молча проигнорировать** — одна из
самых распространенных причин трудноуловимых ошибок:

```python
try:
    process_data()

except Exception:
    pass  # ошибка скрыта: невозможно понять, что пошло не так
```

Правила:

| Вариант | Что перехватывается | Рекомендация |
|---|---|---|
| `except ValueError` | только `ValueError` и типы, входящие в него | предпочтительный вариант |
| `except Exception` | все ошибки прикладного кода | только на верхнем уровне, с журналированием или повторным возбуждением |
| `except BaseException` | все исключения, включая `KeyboardInterrupt` и `SystemExit` | практически не используется |
| `except:` | то же, что `except BaseException`, без доступа к объекту | не использовать |

## 5. Размер блока try

В блок `try` следует помещать **минимум кода**: только те операции, в которых
ожидается исключение. Чем больше код внутри `try`, тем больше риск перехватить
исключение из места, где его не ожидали:

```python
# Плохо: ValueError может прийти из любой из трех строк
def process_age(raw_age: str) -> None:
    try:
        age = int(raw_age)
        discount = calculate_discount(age)
        save_discount(discount)

    except ValueError:
        print(f"Invalid age: {raw_age!r}")
```

Если `ValueError` возникнет внутри `calculate_discount` или `save_discount`,
обработчик выведет сообщение о некорректном возрасте, хотя причина другая.
Лучше ограничить `try` одной операцией, а остальной код вынести за пределы
конструкции. Если при ошибке продолжать выполнение нельзя, в обработчике
завершают выполнение: например, в функции можно выполнить команду `return`:

```python
def process_age(raw_age: str) -> None:
    try:
        age = int(raw_age)

    except ValueError:
        print(f"Invalid age: {raw_age!r}")
        return

    discount = calculate_discount(age)
    save_discount(discount)
```

Теперь `ValueError` из `calculate_discount` и `save_discount` не будет
перехвачен обработчиком, предназначенным для `int(raw_age)`.

## Вывод

- `try ... except` перехватывает исключение, возникшее в блоке `try`.
  Оставшаяся часть блока `try` при этом не выполняется, а после обработки
  выполнение программы продолжается со строки, следующей за блоком `except`.
- `except` перехватывает указанный тип исключения и все типы, входящие в него.
  Если тип не подходит, исключение продолжает распространяться.
- `except ExceptionType as name` дает доступ к объекту исключения; имя доступно
  только внутри блока `except`.
- Блок `try` обязан сопровождаться хотя бы одним `except` или `finally`, иначе
  возникает `SyntaxError`.
- Голый `except:` перехватывает все, включая `KeyboardInterrupt` и
  `SystemExit`, скрывает ошибки в коде и не дает доступа к исключению. Его
  использовать не следует; указывайте конкретные типы исключений.
- `except Exception` перехватывает ошибки прикладного кода и допустим на
  верхнем уровне программы; молчаливое игнорирование исключений недопустимо.
- Блок `try` должен содержать минимум кода.
