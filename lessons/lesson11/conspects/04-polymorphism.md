# Полиморфизм

> **Главная мысль.** **Полиморфизм** — это способность объектов (функций или
> классов) вести себя по-разному в зависимости от входных данных. Например,
> одна и та же функция вызывается единообразно, но принимает объекты разных
> типов и выполняет для них разные действия. В Python для этого не нужны
> специальные синтаксические конструкции: из-за динамической типизации функция
> принимает объект любого типа, а вся логика работы с разными входными данными
> записывается в ее теле или определяется самими объектами.

---

## 1. Полиморфная функция

Рассмотрим функцию, которая складывает два объекта:

```python
from typing import Any


def add(first_term: Any, second_term: Any) -> Any:
    return first_term + second_term


print(add(2, 3))                # 5         -- сумма чисел
print(add(2.5, 1))              # 3.5       -- сумма чисел
print(add("Py", "thon"))        # Python    -- конкатенация строк
print(add([1, 2], [3]))         # [1, 2, 3] -- конкатенация списков
print(add((1, 2), (3,)))        # (1, 2, 3) -- конкатенация кортежей
```

Функция `add` **одна**, и вызывается она всегда **одинаково**:
`add(first, second)`. При этом ее поведение зависит от переданных объектов:
для чисел вычисляется сумма, а для последовательностей выполняется
конкатенация.

Тело функции не содержит проверок типов. Различие в поведении обеспечивают
типы данных: каждый тип сам определяет, как операция сложения выполняется с
его экземплярами. Типы `int`, `str`, `list` и `tuple` являются классами, и
каждый из них задает для оператора `+` свое поведение.

Это тоже полиморфизм: оператор `+` записывается одинаково, а операция
сложения выполняется по-разному в зависимости от типов объектов. В отличие от
полиморфной функции `add`, это уже **полиморфизм на уровне классов**:
различия в поведении определены не в теле функции, а в самих классах.

Функция работает не с любыми объектами, а только с теми, для которых
выполняется операция из ее тела. В остальных случаях возникает обычное
исключение:

```python
print(add(1, "2"))
# TypeError: unsupported operand type(s) for +: 'int' and 'str'
```

### Полиморфизм встроенных функций

Мы уже много раз пользовались полиморфными функциями. Например, `len`
вызывается одинаково для разных контейнеров:

```python
print(len("text"))            # 4 -- количество символов
print(len([1, 2, 3]))         # 3 -- количество элементов списка
print(len({"a": 1, "b": 2}))  # 2 -- количество пар словаря
```

## 2. В Python нет перегрузки функций

В языках со статической типизацией, например в C++ и Java, можно определить
несколько функций с одним именем и разными типами параметров. Этот механизм
называется **перегрузкой функций (function overloading)**: компилятор выбирает
нужную версию по типам аргументов.

В Python такого механизма нет. Инструкция `def` создает объект-функцию и
связывает его с именем. Повторный `def` с тем же именем создает новую функцию
и **перепривязывает** имя к ней, независимо от аннотаций типов и количества
параметров:

```python
def describe(value: int) -> str:
    return f"Number: {value}"


def describe(value: str) -> str:
    return f"String: {value}"


print(describe("text"))  # String: text
print(describe(42))      # String: 42 -- первой функции под этим именем больше нет
```

Аннотации не влияют на выполнение программы,
поэтому выбирать функцию по ним интерпретатор не может.

Перегрузка в Python и не требуется. Параметр функции не связан с
определенным типом: в него можно передать любой объект. Поэтому достаточно
определить **одну** функцию и описать всю необходимую логику в ее теле.

## 3. Явное ветвление в теле функции

Если поведения, которое обеспечивают сами объекты, недостаточно, функция может
проверить тип аргумента и выбрать нужную последовательность действий:

```python
from typing import Any


def describe(value: Any) -> str:
    if isinstance(value, str):
        return f"String of length {len(value)}"

    if isinstance(value, int):
        return f"Integer number: {value}"

    if isinstance(value, list):
        return f"List with {len(value)} items"
    return f"Object of type {type(value).__name__}"


print(describe("text"))     # String of length 4
print(describe(42))         # Integer number: 42
print(describe([1, 2, 3]))  # List with 3 items
print(describe(2.5))        # Object of type float
```

Тем же способом обрабатываются вызовы с разным числом аргументов: для этого
используются значения по умолчанию, `*args` и `**kwargs`:

```python
def calculate_area(width: int, height: int | None = None) -> int:
    if height is None:
        return width * width  # передана одна сторона: квадрат
    return width * height


print(calculate_area(3))     # 9
print(calculate_area(3, 4))  # 12
```

Явными проверками типов не следует злоупотреблять. С каждым новым типом такую
функцию приходится изменять, а цепочка условий растет. Если возможно,
предпочтительнее подход из следующего раздела, при котором поведение
определяется самим объектом.

## 4. Полиморфизм и пользовательские классы

Полиморфизм распространяется и на пользовательские типы. Определим два
независимых класса, у каждого из которых есть метод `get_area`:

```python
class Square:
    def __init__(self, side: float) -> None:
        self.side = side

    def get_area(self) -> float:
        return self.side * self.side


class Triangle:
    def __init__(self, base: float, height: float) -> None:
        self.base = base
        self.height = height

    def get_area(self) -> float:
        return self.base * self.height / 2
```

Функция, вычисляющая общую площадь, работает с объектами обоих классов:

```python
from typing import Any


def get_total_area(figures: list[Any]) -> float:
    total_area = 0

    for figure in figures:
        total_area += figure.get_area()

    return total_area


figures = [Square(3), Triangle(4, 5)]
print(get_total_area(figures))  # 19.0
```

Вызов `figure.get_area()` записан один раз. Какой именно метод будет
выполнен, определяется объектом, на который в данный момент ссылается
`figure`.

Функция `get_total_area` не проверяет типы фигур. Ей важно только наличие
метода `get_area` с подходящей сигнатурой. Такой подход называется
**утиной типизацией (duck typing)**: пригодность объекта определяется не его
типом, а набором его атрибутов и методов. Если у переданного объекта нужного
метода нет, возникнет `AttributeError`:

```python
print(get_total_area([Square(3), "circle"]))
# AttributeError: 'str' object has no attribute 'get_area'
```

Чтобы добавить новую фигуру, достаточно определить класс с методом
`get_area`. Изменять `get_total_area` не нужно. В этом и заключается ценность
полиморфизма: у разных объектов похожий API, поэтому можно писать более
гибкий код, который опирается на поведение объектов, а не на конкретные
типы данных. Такой код работает и с теми типами, которых еще не существовало,
когда он был написан.

## Вывод

- **Полиморфизм** — способность функций и объектов вести себя по-разному с
  разными входными данными при единообразном использовании.
- Функция `add` вызывается одинаково для любых аргументов: числа она
  складывает, а последовательности объединяет. Операция сложения тоже
  полиморфна, но уже на уровне классов: каждый тип сам определяет поведение
  оператора `+` со своими экземплярами.
- В Python **нет перегрузки функций**: повторный `def` перепривязывает имя.
  Особый синтаксис не нужен, поскольку параметр принимает объект любого типа.
- Различия в поведении определяются либо самими объектами (операторы и
  методы), либо явной логикой в теле функции.
- При **утиной типизации** важен не тип объекта, а наличие у него нужных
  атрибутов и методов.
