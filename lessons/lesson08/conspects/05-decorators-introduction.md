# Декораторы: от задачи к синтаксису

> **Главная мысль.** **Декоратор (decorator)** — это функция, которая
> принимает функцию и возвращает другую функцию (обертку) с расширенным
> поведением. Декоратор позволяет
> добавить к функции дополнительную возможность (замер времени, логирование,
> проверку аргументов), **не изменяя ее тела** и не дублируя код. Синтаксис
> `@decorator` над определением функции — это сокращенная запись присваивания
> `function = decorator(function)`. В основе декоратора лежат два механизма,
> которые мы уже изучили: **функции как объекты высшего порядка** и
> **замыкания**.

---

## 1. Постановка задачи: замер времени работы функции

Пусть имеется функция, которая вычисляет сумму квадратов чисел от `0` до
`limit - 1`. Требуется узнать, сколько времени она работает. Для измерения
используем функцию `perf_counter` из модуля `time`: она возвращает значение
высокоточного счетчика в секундах, а время работы равно разности двух
замеров.

### Первая попытка: код замера в теле функции

```python
import time


def compute_sum(limit: int) -> int:
    start_time = time.perf_counter()
    total = 0

    for number in range(limit):
        total += number * number

    elapsed_time = time.perf_counter() - start_time
    print(f"compute_sum took {elapsed_time:.4f} s")

    return total


print(compute_sum(2_000_000))
```

Вывод (значение времени зависит от компьютера):
```
compute_sum took 0.1043 s
2666664666667000000
```

Решение рабочее, но у него два недостатка:

1. **Дублирование.** Если замерять время нужно у десяти функций, один и тот же
   код замера придется скопировать в тела всех десяти. Изменение формата
   вывода потребует правок во всех десяти местах.
2. **Смешение ответственностей.** Функция `compute_sum` должна решать
   математическую задачу. Замер времени — отдельная, **добавочная**
   функциональность, не относящаяся к основной задаче. Она усложняет тело
   функции, затрудняет чтение и сопровождение, а отключить замер можно только
   редактированием функции.

Нужен способ вынести добавочное поведение в одно место и применять его к
любой функции, не трогая ее тела.

## 2. Идея: функция, которая расширяет другую функцию

Вспомним два факта из предыдущих тем:

- функции — обычные объекты, их можно **передавать** в другие функции и
  **возвращать** из функций;
- вложенная функция сохраняет ссылки на переменные объемлющей функции
  (**замыкание**).

Объединим их: напишем функцию, которая **принимает целевую функцию** и внутри
определяет **новую функцию**, вызывающую целевую и дополняющую ее поведение.
Новая функция использует целевую как свободную переменную. Внешняя функция
возвращает новую функцию:

```python
import time
from typing import Any, Callable


def measure_time(function: Callable[..., Any]) -> Callable[..., Any]:
    def wrapper(*args: Any, **kwargs: Any) -> Any:
        start_time = time.perf_counter()
        result = function(*args, **kwargs)
        elapsed_time = time.perf_counter() - start_time
        print(f"{function.__name__} took {elapsed_time:.4f} s")

        return result

    return wrapper
```

Разберем устройство `wrapper` (обертки):

- `function` — свободная переменная: исходная функция, сохраненная в
  замыкании;
- `*args` и `**kwargs` собирают **любые** позиционные и именованные аргументы
  и передают их дальше без изменений (см. конспект про `*args` и `**kwargs`).
  Благодаря этому обертка подходит для функции с любой сигнатурой;
- результат исходной функции сохраняется в `result` и **возвращается**
  оберткой вызывающему коду. Если забыть `return result`, декорированная
  функция всегда будет возвращать `None`;
- замер времени размещен вокруг вызова `function(...)`.

Теперь функция `compute_sum` может снова содержать только основную логику:

```python
def compute_sum(limit: int) -> int:
    total = 0

    for number in range(limit):
        total += number * number

    return total
```

Вызовем `measure_time`, передав `compute_sum`, и сохраним результат в новую
переменную:

```python
timed_compute_sum = measure_time(compute_sum)
print(timed_compute_sum(2_000_000))
```

Вывод:
```
compute_sum took 0.1038 s
2666664666667000000
```

Переменная `timed_compute_sum` ссылается на `wrapper`. Это **исходная функция
с дополненным поведением**: она принимает те же аргументы, возвращает тот же
результат, но дополнительно печатает время работы. Исходная `compute_sum`
при этом не изменилась, и ее по-прежнему можно вызвать без замера.

Эту схему можно применить к любой другой функции:

```python
def multiply_all(numbers: list[int]) -> int:
    result = 1

    for number in numbers:
        result *= number

    return result


timed_multiply_all = measure_time(multiply_all)
print(timed_multiply_all([1, 2, 3, 4]))
```

Вывод:
```
multiply_all took 0.0000 s
24
```

Код замера реализован **в одном месте**, а применяется к произвольному числу функций.

## 3. Перепривязка имени: декоратор

В предыдущем разделе есть неудобство: в программе существуют две функции,
исходная `compute_sum` и дополненная `timed_compute_sum`, а нужна обычно только
вторая. Чтобы везде использовалась версия с замером, в каждом месте программы,
где вызывается `compute_sum`, пришлось бы заменить имя на `timed_compute_sum`.

Имя функции — обычная переменная. Результат вызова `measure_time` можно
сохранить **под прежним именем**, то есть перепривязать идентификатор
исходной функции к новому объекту:

```python
compute_sum = measure_time(compute_sum)
print(compute_sum(2_000_000))
```

Вывод:
```
compute_sum took 0.1041 s
2666664666667000000
```

Теперь все обращения к имени `compute_sum` вызывают версию с замером, а код,
использующий функцию, менять не нужно. Исходная функция остается доступной
только внутри замыкания, как значение свободной переменной `function`.

Именно эта конструкция и называется **декорированием**:

- `compute_sum` — **декорируемая** функция;
- `measure_time` — **декоратор**: функция, которая принимает функцию и
  возвращает функцию-замену с дополненным поведением;
- `compute_sum = measure_time(compute_sum)` — **применение декоратора**.

## 4. Синтаксис `@`

Перепривязка имени после определения функции выглядит громоздко: имя
декорируемой функции (здесь `compute_sum`) приходится указывать три раза (в
`def`, в левой части присваивания и в аргументе вызова декоратора), а применение декоратора отделено от `def`.
Для решения этой проблемы в Python существует специальный синтаксис: строка с символом `@` и
выражением-декоратором **непосредственно над** `def`:

```python
@measure_time
def compute_sum(limit: int) -> int:
    total = 0

    for number in range(limit):
        total += number * number
    return total


print(compute_sum(2_000_000))
```

Вывод:
```
compute_sum took 0.1040 s
2666664666667000000
```

Эта запись **в точности эквивалентна** такой:

```python
def compute_sum(limit: int) -> int:
    ...


compute_sum = measure_time(compute_sum)
```

Интерпретатор выполняет следующие шаги:

1. вычисляет выражение после `@` (здесь — находит объект `measure_time`);
2. выполняет `def` и создает объект исходной функции;
3. вызывает декоратор, передав ему созданную функцию;
4. связывает имя функции (`compute_sum`) с **результатом** вызова декоратора.

Сам символ `@` не добавляет новых возможностей: это только сокращенная запись
присваивания `function = decorator(function)`. Применяемый декоратор при этом
указан непосредственно перед определением функции, и это видно сразу, без
просмотра кода после ее тела.

## 5. После `@` может стоять любой вызываемый объект

Несмотря на то, что в глоссарии Python декоратор определяется как функция,
возвращающая другую функцию, сам синтаксис `@` такого ограничения не
накладывает. Запись `@decorator` раскрывается в `name = decorator(name)`, и для
этого достаточно, чтобы после `@` стоял **вызываемый (callable)** объект,
который можно вызвать с одним позиционным аргументом. Поэтому после `@` могут
стоять:

- пользовательские функции (как `measure_time`);
- встроенные функции и методы;
- объекты любых других вызываемых типов, например классы и объекты с методом
  `__call__` (эти возможности мы рассмотрим после изучения классов).

Наглядный пример — встроенная функция `print`. Декоратором в строгом смысле
она не является, так как не возвращает функцию, но синтаксис `@` ее допускает:
`print` принимает один аргумент и возвращает `None`:

```python
@print
def greet() -> None:
    pass


print(greet)  # None
```

Вывод:
```
<function greet at 0x000001F2A3B4C5E0>
None
```

Запись `@print` эквивалентна `greet = print(greet)`: функция `print` напечатала
объект-функцию и вернула `None`, а имя `greet` оказалось связанным с `None`.
Пример показывает две вещи:

- `@` — только вызов, и использовать в нем можно любой вызываемый объект;
- **возвращаемое значение вызова становится новым значением имени**. Синтаксис
  не требует, чтобы оно было функцией, но настоящий декоратор всегда возвращает
  функцию.

Декорировать можно не только функции. Синтаксис применим и к другому
определению — `class`: запись `@decorator` над классом эквивалентна
`Name = decorator(Name)`. Классы будут изучаться в следующих разделах курса.

## Вывод

- Дополнительную функциональность (замер времени, логирование и т. п.) нецелесообразно
  размещать в теле функции: код дублируется, а основная задача функции
  смешивается с вспомогательной.
- Функция, принимающая другую функцию и возвращающая вложенную функцию-обертку,
  использует замыкание: исходная функция хранится в обертке как свободная
  переменная. Обертка принимает `*args, **kwargs`, вызывает исходную функцию и
  возвращает ее результат.
- Если сохранить результат под прежним именем (`function = decorator(function)`),
  то вместо исходной функции в программе остается только расширенная. Это и
  есть **декоратор**.
- Синтаксис `@decorator` над `def` эквивалентен
  `function = decorator(function)` после определения функции.
- Декоратор — это функция, которая принимает функцию и возвращает функцию. При
  этом синтаксис `@` допускает любой вызываемый объект, принимающий один
  аргумент. Новым значением имени становится то, что вернул вызов. Синтаксис
  `@` применим не только к функциям, но и к классам.
