# Повторение: локальные и глобальные переменные, поиск имен

> **Главная мысль.** Замыкания и декораторы целиком построены на правилах
> видимости имен, поэтому начнем с повторения. Имя, которому **присваивается**
> значение в теле функции, считается **локальным во всем теле** — решение
> принимается при компиляции, до запуска функции. Остальные имена ищутся по
> цепочке **LEGB**: Local → Enclosing → Global → Built-in. Если локальное имя
> читается раньше, чем ему присвоено значение, возникает **`UnboundLocalError`**
> — ошибка, которая выглядит неочевидно, пока неизвестно, как устроена
> символьная таблица функции.

---

## 1. Пространства имен и области видимости

**Пространство имен** — отображение «имя → объект». В программе одновременно
существует несколько независимых пространств имен:

| Пространство имен | Что в нем хранится | Время существования |
|---|---|---|
| **Built-in** | `print`, `len`, `ValueError`, ... | пока работает интерпретатор |
| **Global** | имена верхнего уровня модуля | пока загружен модуль |
| **Enclosing** | локальные имена внешних функций | пока существует вызов внешней функции |
| **Local** | параметры и переменные функции | один вызов функции |

Глобальное пространство имен может быть получено в виде обычного словаря с
помощью вызова `globals()`, локальное — с помощью вызова `locals()`:

```python
tax_rate = 0.2


def calculate_price(price: float) -> float:
    total = price * (1 + tax_rate)

    print(locals())  # {'price': 100, 'total': 120.0}

    return total


calculate_price(100)

print("tax_rate" in globals())  # True
```

Локальное пространство имен создается заново при **каждом вызове** функции и
удаляется при ее завершении. Именно этот факт будет принципиально важен при
изучении замыканий.

## 2. Поиск имен: правило LEGB

При **чтении** имени Python последовательно просматривает пространства имен
четырех видов (областей видимости) и останавливается на первом, где имя
найдено:

1. **L**ocal — локальное пространство текущей функции;
2. **E**nclosing — локальные пространства объемлющих функций (от ближайшей к
   самой внешней);
3. **G**lobal — пространство имен модуля;
4. **B**uilt-in — встроенные имена.

Если имя не найдено ни в одном из этих пространств, возникает `NameError`.

```python
level = "global"


def outer() -> None:
    level = "enclosing"

    def inner() -> None:
        print(level)  # enclosing -- в L имени нет, найдено в E

    inner()


outer()       # enclosing
print(level)  # global
```

Правило LEGB описывает только **чтение**. Любое **присваивание** имени внутри
функции создает (или обновляет) имя в ее **локальном** пространстве. Глобальная
переменная при этом не изменяется:

```python
counter = 0


def reset_counter() -> None:
    counter = 100  # новая локальная переменная, а не изменение глобальной


reset_counter()
print(counter)  # 0
```

## 3. Символьная таблица: классификация имен до выполнения

Перед выполнением функции Python компилирует ее тело и строит **символьную
таблицу**: каждое имя классифицируется заранее. Правило классификации:

- если имя является параметром функции или ему **присваивается значение**
  где угодно в теле функции (`=`, `+=`, `for`, `import`, `def`,
  `with ... as`), то оно считается **локальным во всем теле** функции;
- если имя в теле только читается и нигде не присваивается, то оно считается
  **внешним** и ищется в областях видимости E, G, B.

Результат классификации хранится в объекте кода функции:

```python
rate = 2


def calculate(price: float, count: int) -> float:
    total = price * count
    return total * rate


print(calculate.__code__.co_varnames)  # ('price', 'count', 'total') -- локальные имена
print(calculate.__code__.co_names)     # ('rate',) -- внешние глобальные имена
```

Ключевой момент: классификация выполняется **один раз до запуска** функции и
не зависит от того, в каком порядке выполняются строки и выполняются ли они
вообще. Достаточно, чтобы присваивание **присутствовало в тексте** тела.

## 4. UnboundLocalError

Исключение **`UnboundLocalError`** возникает, когда программа читает локальную
переменную раньше, чем ей было присвоено значение. Оно является подклассом
`NameError`:

```python
print(issubclass(UnboundLocalError, NameError))  # True
```

Различие между двумя ошибками такое:

- `NameError` — имя не найдено ни в одной из областей видимости LEGB;
- `UnboundLocalError` — по символьной таблице имя является локальным, но на
  момент чтения значение этому имени еще не присвоено.

### Чтение до присваивания

```python
value = 10


def show_value() -> None:
    print(value)  # UnboundLocalError: cannot access local variable 'value'
                  # where it is not associated with a value
    value = 20


show_value()
```

Можно предположить, что `print(value)` выведет глобальное `10`, а затем будет
создана локальная переменная. Но присваивание `value = 20` в теле функции
делает `value` локальным именем **во всем теле**, в том числе в строках,
предшествующих присваиванию. Поиск по LEGB для такого имени не выполняется: интерпретатор
обращается только к локальному пространству, где значения еще нет.

Убедиться в этом можно по символьной таблице:

```python
print(show_value.__code__.co_varnames)  # ('value',) -- value локальное
print(show_value.__code__.co_names)     # ('print',)
```

### Составное присваивание глобальной переменной

Чаще всего `UnboundLocalError` возникает при попытке изменить глобальный
счетчик внутри функции:

```python
counter = 0


def increment() -> None:
    counter += 1  # UnboundLocalError


increment()
```

Запись `counter += 1` содержит присваивание имени `counter`, поэтому
`counter` считается локальной переменной. При этом операция сначала читает
текущее значение `counter`, прибавляет к нему `1` и только потом записывает
результат обратно. Чтение выполняется из локального пространства имен, где у
`counter` еще нет значения, поэтому возникает `UnboundLocalError`. Запись
`counter = counter + 1` ведет себя так же.

Для изменяемых объектов ситуация зависит от вида операции. Вызов метода — это
**чтение имени** с последующим обращением к объекту, поэтому ошибки нет.
Составное присваивание — это **присваивание имени**, поэтому ошибка есть,
даже если объект является списком:

```python
history = []


def add_with_method(item: str) -> None:
    history.append(item)  # работает: имя history только читается


def add_with_operator(item: str) -> None:
    history += [item]     # UnboundLocalError: history -- локальное имя


add_with_method("first")
print(history)  # ['first']
add_with_operator("second")
```

### Присваивание в условной ветке

Ошибка может возникать не при каждом вызове функции, а только в определенных
ветках выполнения программы. Классификация имени как локального выполняется
заранее и от выбранной ветки не зависит:

```python
def get_label(temperature: int) -> str:
    if temperature > 25:
        label = "hot"

    return label  # UnboundLocalError при temperature <= 25


print(get_label(30))  # hot
print(get_label(10))  # UnboundLocalError
```

Имя `label` локальное при любом значении `temperature`, но значение ему
присваивается только в одной из ветвей. Аналогично ведет себя переменная
цикла, если цикл не выполнил ни одной итерации:

```python
def get_last_item(items: list[int]) -> int:
    for item in items:
        pass

    return item  # UnboundLocalError при пустом списке


print(get_last_item([1, 2, 3]))  # 3
print(get_last_item([]))         # UnboundLocalError
```

### Параметр с тем же именем

Параметр — всегда локальное имя со значением, поэтому ошибки не будет, но
глобальное имя оказывается недоступным:

```python
level = 5


def show_level(level: int) -> None:
    print(level)  # значение берется из аргумента, а не из модуля


show_level(1)  # 1
```

## 5. Как избежать ошибки

Есть три способа, в порядке предпочтения:

1. **Передать данные через параметры и вернуть результат.** Функция не зависит
   от состояния модуля, ее проще понимать и проверять:

   ```python
   def increment(counter: int) -> int:
       return counter + 1


   counter = 0
   counter = increment(counter)

   print(counter)  # 1
   ```

2. **Инициализировать локальное имя на всех путях выполнения**, например
   присвоить значение по умолчанию до условия:

   ```python
   def get_label(temperature: int) -> str:
       label = "normal"

       if temperature > 25:
           label = "hot"

       return label
   ```

3. **Явно объявить, что имя относится к внешней области видимости**, с помощью
   ключевых слов `global` и `nonlocal`. Этому посвящен следующий конспект.

## Вывод

- Пространства имен независимы: built-in, global, enclosing и local. Локальное
  пространство создается заново при каждом вызове функции.
- При чтении имя ищется по цепочке **LEGB**; при присваивании — всегда
  создается или обновляется локальное имя.
- Классификация имен выполняется при компиляции функции. Если имя
  присваивается в любом месте тела функции (в том числе через `+=`, `for`,
  `import`), то оно является локальным **во всем теле этой функции**, включая
  строки, предшествующие присваиванию.
- `UnboundLocalError` (подкласс `NameError`) возникает, когда локальное имя
  читается раньше, чем ему присвоено значение. Типичные случаи: чтение до
  присваивания, `+=` над внешней переменной, присваивание только в одной ветке
  условия.
- Вызов метода изменяемого объекта (`history.append(...)`) не является
  присваиванием имени, а потому допустим.
