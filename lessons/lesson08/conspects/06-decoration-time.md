# Время применения декоратора

> **Главная мысль.** Декоратор вызывается **один раз — в момент выполнения
> инструкции определения (`def`) декорируемой функции**, а не при вызове этой
> функции. В жизни декорированной функции есть два разных момента: **время декорирования**
> (выполняется тело декоратора, создается обертка) и **время вызова** (каждый
> раз выполняется тело обертки). Если функция определена на верхнем уровне
> модуля, декорирование происходит при **загрузке (импорте) модуля**. Это
> свойство используют декораторы-регистраторы, которые ничего не оборачивают, а
> только запоминают функцию.

---

## 1. Два момента: декорирование и вызов

Напомним, что `def` — исполняемая инструкция. Строки

```python
@decorator
def function() -> None:
    ...
```

выполняются как `function = decorator(function)` в тот момент, когда
управление доходит до `def`. Проверим это, добавив в декоратор вывод как
снаружи обертки, так и внутри нее:

```python
from typing import Any, Callable


def announce(function: Callable[..., Any]) -> Callable[..., Any]:
    print(f"Decorating {function.__name__}")  # выполняется при декорировании

    def wrapper(*args: Any, **kwargs: Any) -> Any:
        print(f"Calling {function.__name__}")  # выполняется при каждом вызове
        return function(*args, **kwargs)
    return wrapper


print("Program started")


@announce
def say_hello() -> None:
    print("Hello")


print("Function defined")
say_hello()
say_hello()
```

Вывод:
```
Program started
Decorating say_hello
Function defined
Calling say_hello
Hello
Calling say_hello
Hello
```

Порядок вывода показывает последовательность событий:

1. `Program started` — выполнена строка, предшествующая определению
   `say_hello`;
2. `Decorating say_hello` — выполнено **тело декоратора** `announce`; это
   произошло при выполнении инструкции `def say_hello`, еще до первого вызова
   `say_hello`;
3. `Function defined` — управление вернулось после определения `say_hello`;
4. `Calling say_hello` — выполняется **тело обертки**; это происходит заново
   при каждом вызове.

Следствие: код в теле декоратора **вне** `wrapper` выполняется один раз для
каждой декорируемой функции, а код **внутри** `wrapper` — при каждом вызове
декорированной функции.

| Где размещен код | Когда выполняется | Типичное назначение |
|---|---|---|
| В теле декоратора, вне `wrapper` | один раз при декорировании | подготовка: регистрация, создание начального состояния |
| В теле `wrapper` до вызова `function` | при каждом вызове, до функции | проверка аргументов, запуск таймера, запись в журнал |
| В теле `wrapper` после вызова `function` | при каждом вызове, после функции | обработка результата, остановка таймера |

## 2. Состояние, создаваемое при декорировании

Поскольку тело декоратора выполняется при каждом декорировании отдельной
функции, переменные этого тела создаются **заново для каждой декорируемой
функции**. Их используют для хранения состояния, связанного с конкретной
функцией. Пример — подсчет числа вызовов:

```python
from typing import Any, Callable


def count_calls(function: Callable[..., Any]) -> Callable[..., Any]:
    calls_count = 0  # создается при декорировании, отдельно для каждой функции

    def wrapper(*args: Any, **kwargs: Any) -> Any:
        nonlocal calls_count
        calls_count += 1
        print(f"{function.__name__} called {calls_count} time(s)")
        return function(*args, **kwargs)
    return wrapper


@count_calls
def first_function() -> None:
    pass


@count_calls
def second_function() -> None:
    pass


first_function()   # first_function called 1 time(s)
first_function()   # first_function called 2 time(s)
second_function()  # second_function called 1 time(s)
```

Декоратор `count_calls` применен дважды, поэтому его тело выполнено два раза и
создало две независимые переменные `calls_count` в двух замыканиях.

## 3. Когда определение функции выполняется повторно

Декорирование выполняется при **каждом выполнении инструкции определения
(`def`) декорируемой функции**. Для функции на верхнем уровне модуля это
происходит один раз, но если функция определяется
внутри другой функции, то декорируется заново при каждом вызове внешней:

```python
from typing import Any, Callable


def announce(function: Callable[..., Any]) -> Callable[..., Any]:
    print(f"Decorating {function.__name__}")
    return function


def outer() -> None:
    @announce
    def inner() -> None:
        pass


outer()  # Decorating inner
outer()  # Decorating inner -- def выполнен повторно
```

Это справедливо и для кода, в котором `def` расположен внутри цикла или
условия: декоратор вызывается каждый раз, когда выполняется инструкция
определения (`def`) декорируемой функции.

## 4. Время импорта и декораторы-регистраторы

Если функция определена на верхнем уровне модуля, то декорирование
выполняется при **загрузке модуля**: в момент запуска скрипта или при первом
`import`. Тела всех функций к этому моменту еще не выполнены, но декораторы
уже отработали.

На этом основан часто используемый прием — **регистрация**. Декоратор не
оборачивает функцию, а только запоминает ее в общем хранилище и возвращает
**ту же самую функцию** без изменений:

```python
from typing import Callable

commands: dict[str, Callable[[], None]] = {}


def register(function: Callable[[], None]) -> Callable[[], None]:
    commands[function.__name__] = function
    return function


@register
def start() -> None:
    print("Starting")


@register
def stop() -> None:
    print("Stopping")


print(list(commands))  # ['start', 'stop'] -- функции еще ни разу не вызывались
commands["start"]()    # Starting
commands["stop"]()     # Stopping
```

В результате словарь `commands` пополняется в момент определения каждой
функции, помеченной `@register`, а добавление новой команды сводится к написанию функции с декоратором
`@register`: изменять словарь вручную не нужно. Так устроены многие
библиотеки: веб-фреймворки привязывают к адресам обработчики запросов,
тестовые фреймворки собирают тестовые функции, системы плагинов собирают
расширения.

Побочный эффект такого подхода: **простой импорт модуля уже запускает код
декораторов**. Если декоратор выполняет тяжелые или опасные действия
(обращение к сети, запись в файл), они произойдут при импорте, а не при
вызове функции.

## Вывод

- Декоратор вызывается в момент выполнения инструкции определения (`def`)
  декорируемой функции: для функции верхнего уровня — при загрузке модуля, для
  вложенной — при каждом выполнении внешней функции.
- Код в теле декоратора вне `wrapper` выполняется один раз при декорировании;
  код в теле `wrapper` — при каждом вызове декорированной функции.
- Переменные тела декоратора создаются отдельно для каждой декорируемой
  функции и сохраняются в замыкании, поэтому подходят для хранения состояния
  (например, счетчика вызовов, изменяемого через `nonlocal`).
- Декоратор может не создавать обертку, а вернуть исходную функцию. Так
  работают декораторы-регистраторы, пополняющие реестры при импорте модуля.
