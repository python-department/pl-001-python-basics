# Как интерпретатор запускает программу

> **Главная мысль.** Между вызовом интерпретатора и получением результата выполнения программы
> интерпретатор проделывает четыре шага: **читает** исходный код, **разбирает** (парсит) его,
> **компилирует** в промежуточный байткод и только потом **исполняет** этот
> байткод. Python одновременно и компилируемый, и интерпретируемый язык — просто
> компилируется он не в машинный код, а в специальный python-байткод.

---

## Конвейер: от текста к результату

```
исходный код (.py)
      │
      ▼
1. Чтение исходного кода      →  просто текст: строки, отступы, комментарии
      │
      ▼
2. Парсинг (разбор)           →  токены → дерево разбора (AST)
      │
      ▼
3. Компиляция в байткод       →  список простых инструкций для виртуальной машины
      │
      ▼
4. Исполнение (интерпретация) →  виртуальная машина выполняет байткод,
      │                           создавая и изменяя объекты
      ▼
   результат работы программы
```

---

## Шаг 1. Чтение исходного кода

Интерпретатор открывает файл `.py` и читает его содержимое как текст, записанный в кодировке
UTF-8.

При чтении и парсинге исходного кода для интерпретатора Python важны вещи, 
которые в других языках несущественны:

- где заканчивается строка (перевод строки — значимый символ)
- сколько пробелов стоит в начале строки (**отступы** в Python определяют
  вложенность блоков)

Подробнее об анатомии Python-файла написано в [следующем конспекте](./03-anatomy-of-a-python-file.md).

---

## Шаг 2. Парсинг (разбор)

Парсинг превращает плоский текст в структуру, отражающую смысл программы. Он состоит из
двух этапов.

### 2.1. Лексический анализ: текст → токены

**Токенизатор** (лексер) разбивает текст на **токены** — минимальные значимые
единицы программы: идентификаторы, ключевые слова, литералы, операторы, разделители. Пробелы между
токенами отбрасываются, а отступы превращаются в специальные токены `INDENT` и `DEDENT`. 
Эти токены используются для учета уровней отступа блоков кода.

Так, например, строка исходного кода `total = price * 2` будет преобразована в следующий поток токенов:

```
NAME 'total'   OP '='   NAME 'price'   OP '*'   NUMBER '2'   NEWLINE
```

Посмотреть своими глазами можно модулем `tokenize`:

```console
$ python -m tokenize hello.py
```

Подробнее о токенах написано в [одном из следующих конспектов](./04-tokens.md) этого занятия.

### 2.2. Синтаксический анализ: токены → дерево (AST)

Парсер проверяет, что токены идут в допустимом порядке (соответствуют
**грамматике** языка), и строит **абстрактное синтаксическое дерево** (AST) —
представление программы в виде вложенных узлов. Например, «присваивание», внутри —
«операция умножения», внутри — «имя» и «число».

Если токены нарушают грамматику, программа даже не начнет выполняться —
интерпретатор сразу возбудит исключение `SyntaxError`.

---

## Шаг 3. Компиляция в байткод

AST компилируется в **байткод** — длинный список очень простых команд для
**виртуальной машины Python** (Python Virtual Machine, PVM). Байткод не привязан к конкретному процессору: 
это «машинный код» для воображаемого стекового компьютера.

Именно байткод кэшируется в файлах `.pyc` внутри папки `__pycache__`, чтобы при
последующих запусках одного и того же кода не выполнять парсинг и компиляцию заново.

Увидеть байткод, которым будет представлен код вашей программы, помогает модуль стандартной библиотеки `dis` (сокращение от *disassemble*):

```python
import dis

def total(price):
    return price * 2

dis.dis(total)
```

```
  2           RESUME                   0

  3           LOAD_FAST                0 (price)
              LOAD_CONST               1 (2)
              BINARY_OP                5 (*)
              RETURN_VALUE
```

Полученный байткод можно читать следующим образом: «положи на стек `price`, положи на стек `2`,
перемножь верхушку стека, верни результат».

---

## Шаг 4. Исполнение (интерпретация)

Виртуальная машина берет инструкции байткода **одну за другой** и выполняет их,
поддерживая стек значений и создавая объекты. Это и есть «интерпретация»:
никакого перевода в машинный код процессора не происходит — цикл PVM просто
проходит по байткоду.

---

## Python компилируемый или интерпретируемый язык?

Подобный вопрос может возникнуть, потому что обычно эти термины
противопоставляют друг другу. Принято считать, что язык может или компилироваться, или
интерпретироваться. Однако на примере Python видно, что это неверный взгляд, потому что:

- Python **компилируется** — но не в машинный код процессора, а в переносимый
  python-байткод.
- Python **интерпретируется** — виртуальная машина исполняет этот байткод, а не
  передает его напрямую процессору.

Компиляция в Python быстрая и незаметная, поэтому кажется, что ее нет. На самом деле она
есть — просто ее результат промежуточный, а не финальный. Это отличает Python от компилируемых 
языков программирования, типа C, где компилятор сразу порождает машинный код под конкретный
процессор, и отдельная программа-исполнитель для выполнения программы не нужна.

## Вывод

| Шаг | Вход | Выход | Ошибки этого шага |
|---|---|---|---|
| 1. Чтение | файл `.py` | текст, строки, отступы | проблемы кодировки |
| 2а. Токенизация | текст | поток токенов | недопустимый символ |
| 2б. Парсинг | токены | дерево AST | `SyntaxError`, `IndentationError` |
| 3. Компиляция | AST | байткод (`.pyc`) | редкие внутренние ошибки |
| 4. Исполнение | байткод | результат работы | `NameError`, `TypeError` и прочие — уже во время работы |

Ключевой вывод: **синтаксические ошибки ловятся до запуска** (на шагах 2–3), а
ошибки вроде «переменная не определена» или «неправильный тип» — **только во
время исполнения** (шаг 4), когда до соответствующей инструкции дойдет очередь.
