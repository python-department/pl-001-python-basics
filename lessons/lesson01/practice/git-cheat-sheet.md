# Шпаргалка по основным командам Git

Краткий конспект команд, которые понадобятся в повседневной работе с Git.

## Начало работы с репозиторием

### `git init`

Инициализирует новый Git-репозиторий в текущей папке — создает каталог `.git`, где будет храниться вся история изменений. Используйте, когда хотите начать версионировать проект с нуля.

```console
git init
```

### `git clone`

Скачивает (клонирует) существующий репозиторий с удаленного сервера вместе со всей его историей. Используйте, чтобы получить локальную копию чужого или своего проекта, уже находящегося на GitHub/GitLab и т.п.

```console
git clone <url> [folder_name]
```

## Индексация и фиксация изменений

### `git status`

Показывает текущее состояние рабочей копии: какие файлы изменены, какие добавлены в индекс, а какие вообще не отслеживаются Git. Используйте перед `add`/`commit`, чтобы понимать, что именно вы сохраняете.

```console
git status
```

### `git status -s`

Та же информация, но в сжатом виде — одна строка на файл. Удобно, когда изменений много и полный вывод `git status` избыточен.

```console
git status -s
```

### `git add`

Добавляет изменения (новые или измененные файлы) в индекс — список того, что попадет в следующий коммит. Используйте после того, как проверили изменения через `git status`.

```console
git add <file_1> <file_2> ...
git add .          # добавить все изменения сразу
```

### `git commit`

Фиксирует все проиндексированные изменения в истории репозитория со снимком проекта и сообщением. Используйте, когда хотите сохранить логически завершенный набор изменений.

```console
git commit -m "Add feature X"
```

### `git rm`

Удаляет файл из рабочей копии **и** из индекса одновременно — при следующем коммите файл пропадет из репозитория. Используйте, когда файл больше не нужен ни на диске, ни под версионированием.

```console
git rm <file_name>
```

### `git rm --cached`

Убирает файл только из индекса (из-под контроля Git), но оставляет его на диске. Используйте, когда файл случайно попал под версионирование (например, забыли добавить в `.gitignore`), но физически он вам еще нужен.

```console
git rm --cached <file_name>
```

## История изменений

### `git log`

Показывает историю коммитов: хеш, автора, дату и сообщение каждого коммита. Используйте, чтобы посмотреть, что и когда менялось в проекте.

```console
git log
```

### `git reset`

Перемещает текущую ветку на указанный коммит, отменяя более поздние коммиты. **Важно**: переписывает историю, поэтому применяйте только к коммитам, которые еще не отправлены в общий репозиторий или над которыми точно больше никто не работает.

```console
git reset <mode> <commit_hash>
```

Режимы:

- `--soft` — откатывает коммиты, но все изменения остаются в индексе (готовы к новому коммиту).
- `--mixed` (по умолчанию) — откатывает коммиты, изменения остаются в рабочей копии, но убираются из индекса (перед коммитом снова понадобится `git add`).
- `--hard` — откатывает коммиты и **полностью удаляет** все изменения, включая рабочую копию. Дважды подумайте перед использованием — данные восстановить будет нельзя.

## Работа с удаленными репозиториями

### `git remote`

Показывает список коротких имен удаленных репозиториев, с которыми связан текущий локальный репозиторий (например, `origin`).

```console
git remote
```

### `git remote -v`

То же самое, но с указанием URL для каждого удаленного репозитория (отдельно для fetch и push). Используйте, чтобы проверить, куда именно смотрит `origin`.

```console
git remote -v
```

### `git remote add`

Добавляет новый удаленный репозиторий под заданным именем. Используйте, если репозиторий создавался через `git init` и еще не связан ни с одним удаленным сервером.

```console
git remote add <name> <url>
```

### `git remote remove`

Удаляет удаленный репозиторий из списка связанных с текущим локальным репозиторием. Используйте, если удаленный репозиторий больше не нужен (например, сменили сервер).

```console
git remote remove <name>
```

### `git push`

Отправляет закоммиченные локальные изменения в удаленный репозиторий. Используйте, чтобы поделиться своей работой или сохранить резервную копию на сервере.

```console
git push
```

### `git pull`

Скачивает изменения из удаленного репозитория и сразу применяет их к текущей локальной ветке. Используйте, чтобы получить актуальную версию проекта перед началом работы.

```console
git pull
```
