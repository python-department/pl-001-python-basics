# Характеристики языка Python

> **Определение.** Python — это мультипарадигмальный высокоуровневый язык программирования
> общего назначения с динамической строгой типизацией и автоматическим управлением памятью.

Ниже разбирается каждая характеристика из этого определения.

---

## 1. Мультипарадигмальный язык программирования

**Парадигма программирования** — это способ мышления о программе, набор идей и подходов,
определяющих, как мы структурируем код и описываем вычисления.

**Мультипарадигмальный язык** — язык, который не навязывает один-единственный подход,
а позволяет использовать несколько парадигм и свободно их сочетать в рамках одного проекта.

### Две большие группы парадигм: императивная и декларативная

Все парадигмы принято делить на два больших семейства по тому, **что именно программист
пишет в коде**.

| | Императивная | Декларативная |
|---|---|---|
| Что описываем | **КАК** получить результат: пошаговый алгоритм | **ЧТО** мы хотим получить: результат и правила |
| Ключевые элементы | инструкции, циклы, присваивания, изменение состояния | выражения, функции, описания, запросы |
| Кто отвечает за «как» | программист | язык / среда выполнения |
| Аналогия | рецепт: «нарежь, обжарь, посоли» | заказ в кафе: «хочу борщ» |
| Парадигмы-примеры | процедурная, объектно-ориентированная | функциональная |

Важно: это не «или-или». Один и тот же язык (и Python в том числе) даёт средства обоих
семейств, а конкретную строку кода можно написать в более императивном или более
декларативном стиле.

---

### Императивная парадигма — описываем КАК

Программа — это **последовательность команд (инструкций)**, которые шаг за шагом меняют
состояние программы (значения переменных, содержимое структур данных). Программист явно
управляет порядком действий: заводит счётчики, пишет циклы, вручную накапливает результат.

```python
# Императивно: сумма чётных чисел от 1 до 10
total = 0                      # завели переменную-накопитель

for number in range(1, 11):    # сами организовали перебор
    if number % 2 == 0:        # сами проверяем условие
        total += number        # сами меняем состояние

print(total)  # 30
```

К императивному семейству относят две парадигмы.

**Процедурная парадигма** — код группируется в процедуры (функции), которые вызывают
друг друга.

```python
def read_prices():
    return [100, 200, 50]

def calculate_total(prices):
    total = 0

    for price in prices:
        total += price

    return total

def main():
    prices = read_prices()
    print(calculate_total(prices))  # 350

main()
```

**Объектно-ориентированная парадигма (ООП)** — состояние и меняющие его действия
объединяются в объекты (атрибуты + методы), но внутри методов мы по-прежнему пишем
пошаговые инструкции.

```python
class BankAccount:
    def __init__(self, balance=0):
        self.balance = balance          # состояние объекта

    def deposit(self, amount):
        self.balance += amount          # пошагово меняем состояние

account = BankAccount()
account.deposit(500)
print(account.balance)  # 500
```

---

### Декларативная парадигма — описываем ЧТО

Программа описывает **желаемый результат и правила его получения**, а конкретные шаги
(циклы, счётчики, порядок обхода) берёт на себя язык или библиотека. Кода меньше,
он ближе к формулировке задачи, а не к алгоритму.

Основной декларативный инструмент в Python — **функциональная парадигма**: вычисления
описываются как применение функций; поощряются чистые функции без побочных эффектов,
функции высшего порядка (`map`, `filter`, `reduce`), неизменяемость данных.

```python
from functools import reduce

prices = [100, 200, 50]

# Описываем преобразования, а не циклы:
total = reduce(lambda acc, x: acc + x, prices, 0)   # "свернуть список сложением"
cheap = list(filter(lambda p: p < 150, prices))     # "оставить цены меньше 150"

print(total)     # 350
print(cheap)     # [100, 50]
```

Ещё более декларативны отдельные предметные языки, которые используют вместе с Python:
SQL-запрос описывает, *какие* строки нужны, а не *как* их искать; регулярное выражение
описывает *шаблон* текста, а не алгоритм посимвольного разбора.

---

### Один и тот же результат в двух стилях

```python
words = ["python", "go", "rust", "c", "java"]

# Императивно: как отобрать короткие слова
short_imperative = []

for word in words:
    if len(word) <= 4:
        short_imperative.append(word.upper())

# Декларативно: описываем через функции высшего порядка —
# "отфильтровать короткие слова, к каждому применить upper"
short_declarative = list(map(str.upper, filter(lambda word: len(word) <= 4, words)))

print(short_imperative)   # ['GO', 'RUST', 'C', 'JAVA']
print(short_declarative)  # ['GO', 'RUST', 'C', 'JAVA']
```

**Вывод:** Python мультипарадигмальный, потому что поддерживает оба семейства —
и императивное (процедурный и объектно-ориентированный стиль), и декларативное
(функциональный стиль, генераторы, интеграция с SQL/regex). Программист выбирает: где-то
удобнее явно расписать алгоритм, где-то — коротко описать желаемый результат, а часто
эти стили комбинируются в одном проекте и даже в одной функции.

## 2. Высокоуровневый язык программирования

**Уровень языка** показывает, насколько язык абстрагирован (удалён) от «железа» —
процессора, регистров, ячеек памяти.

- **Низкоуровневые языки** (машинный код, ассемблер) работают напрямую с командами
  процессора и адресами памяти. Код быстрый, но сложный, длинный и привязан к конкретной
  архитектуре.
- **Высокоуровневые языки** (Python, Java, C#, JavaScript) оперируют понятиями, близкими
  к человеку: переменные, списки, словари, функции, объекты. Детали работы с памятью и
  процессором скрыты.

### Что скрывает Python от программиста

| Низкий уровень | В Python |
|---|---|
| Ручное выделение и освобождение памяти | Автоматически (сборщик мусора) |
| Работа с регистрами и адресами | Нет, есть переменные и объекты |
| Управление стеком вызовов | Скрыто интерпретатором |

### Пример: одно и то же действие

Условный «низкий уровень» (псевдо-ассемблер) — сложить два числа:

```
MOV AX, 2
MOV BX, 3
ADD AX, BX      ; результат в регистре AX
```

Python:

```python
result = 2 + 3
print(result)  # 5
```

Одна строка вместо нескольких команд с регистрами. Ещё нагляднее — работа со строками
и структурами данных:

```python
users = ["Аня", "Борис", "Вика"]
users.append("Глеб")
users.sort()
print(users)  # ['Аня', 'Борис', 'Вика', 'Глеб']
```

На низком уровне за этим стоят сотни машинных инструкций, выделение памяти под массив,
его расширение и алгоритм сортировки — но программист этого не видит.

**Плата за удобство:** высокоуровневый код обычно работает медленнее низкоуровневого,
потому что абстракции и интерпретатор добавляют накладные расходы.

## 3. Язык программирования общего назначения

**Язык общего назначения** (general-purpose) — язык, не заточенный под одну узкую область.
На нём можно решать задачи из самых разных сфер.

Противоположность — **предметно-ориентированные языки** (DSL, domain-specific):

- **SQL** — только запросы к базам данных;
- **HTML/CSS** — только разметка и стилизация веб-страниц;
- **Regex** — только описание шаблонов текста.

### Где применяют Python

- веб-разработка (Django, FastAPI, Flask);
- анализ данных и Data Science (pandas, NumPy);
- машинное обучение (PyTorch, scikit-learn);
- автоматизация и скрипты (обработка файлов, парсинг);
- DevOps и системное администрирование;
- тестирование (pytest);
- десктопные приложения (PyQt, Tkinter);
- научные вычисления.

**Вывод:** если один и тот же язык подходит и для веб-сервера, и для нейросети, и для
маленького скрипта — это и есть «общее назначение».

## 4. Динамическая типизация

**Тип данных** — характеристика объекта, определяющая, что это (число, строка, список…)
и какие операции с ним допустимы.

**Типизация** — правила, по которым язык связывает типы с переменными и выражениями.

### Динамическая vs статическая

**Статическая типизация** (C, C++, Java, Go): тип переменной известен и проверяется
на этапе **компиляции**, до запуска программы. Тип обычно указывается явно, и его нельзя
поменять.

```java
// Java
int age = 25;
age = "двадцать пять"; // ОШИБКА ещё на этапе компиляции
```

**Динамическая типизация** (Python, JavaScript, Ruby): тип определяется во время
**выполнения** программы. Тип привязан не к переменной, а к значению (объекту).
Переменная — это просто «ярлык», который можно повесить на объект любого типа.

```python
age = 25          # сейчас в age связан с int
print(type(age))  # <class 'int'>

age = "двадцать пять"  # теперь в age связан с str — это допустимо
print(type(age))       # <class 'str'>
```

### Следствия динамической типизации

**Плюсы:** меньше кода, быстрее прототипирование, гибкость.

**Минусы:** часть ошибок обнаруживается только во время выполнения, а не заранее.

```python
def add(a, b):
    return a + b

print(add(2, 3))        # 5
print(add("2", "3"))    # "23" — тоже "работает", но, возможно, не то, что хотели
print(add(2, "3"))      # TypeError выскочит только при вызове этой строки
```

> **Аннотации типов.** В Python есть подсказки типов (`def add(a: int, b: int) -> int:`),
> но интерпретатор их **не проверяет** — это подсказки для разработчика и внешних
> инструментов (mypy, IDE). Язык остаётся динамически типизированным.

## 5. Строгая типизация

**Строгая (сильная) типизация** описывает, насколько компилятор или интерпретатор
склонен к неявным преобразованиям типов данных.

**Строгая типизация** (Python): компилятор или интерпретатор **не** делает «магических»
неявных преобразований между несовместимыми типами. Хочешь сложить число и строку — преобразуй явно.

```python
"Возраст: " + 25
# TypeError: can only concatenate str (not "int") to str

"Возраст: " + str(25)   # 'Возраст: 25' — так правильно
```

**Слабая типизация** (JavaScript, PHP, C): компилятор или интерпретатор может самостоятельно
выполнять неявные преобразования, что порой приводит к неожиданным результатам.

```javascript
// JavaScript — слабая типизация
"5" + 3     // "53"  (число превратилось в строку)
"5" - 3     // 2     (строка превратилась в число)
[] + {}     // "[object Object]"
```

Строгость типизации не является бинарным признаком. На строгость типизации стоит смотреть, как на спектр.
Один и тот же язык программирования может иметь более или менее строгую типизацию в зависимости от того, с
каким другим языком программирования мы будем его сравнивать.

### Важно: строгая и динамическая — это про разное

Это **две независимые оси**:

| | Статическая | Динамическая |
|---|---|---|
| **Строгая** | Java, C#, Go | **Python**, Ruby |
| **Слабая** | C | JavaScript, PHP |

- *Динамическая* — **когда** проверяется тип - во время выполнения.
- *Строгая* — **насколько допустимы** неявные преобразования типов - неявных преобразований почти нет.

Python: тип узнаётся на лету (динамическая), но неявных преобразований типов почти не происходит (строгая).

```python
x = 10
y = "20"

# Python не станет угадывать, что вы имели в виду:
x + y            # TypeError
x + int(y)       # 30   — явное преобразование
str(x) + y       # '1020' — тоже явное, другой смысл
```

## 6. Автоматическое управление памятью

Любой программе нужно выделять память под данные (объекты) и освобождать её, когда данные
больше не нужны. Есть два подхода:

### Ручное управление (C, C++)

Программист сам выделяет и освобождает память.

```c
int *arr = malloc(100 * sizeof(int)); // выделили
// ... работаем ...
free(arr);                            // обязаны освободить вручную
```

Ошибки такого подхода:

- **утечка памяти** — забыли `free`, память не вернулась системе;
- **висячий указатель** — обратились к уже освобождённой памяти;
- **двойное освобождение** — вызвали `free` дважды.

### Автоматическое управление (Python)

Программист просто создаёт объекты и не думает об их удалении — за это отвечает сам
интерпретатор. В CPython работают два **дополняющих друг друга** механизма: это не
альтернативы, а два уровня одной системы, каждый закрывает то, что не может другой.

**1. Подсчёт ссылок (reference counting) — основной механизм.**
Каждый объект хранит счётчик — сколько ссылок на него сейчас существует (имена,
элементы контейнеров, аргументы функций…). Интерпретатор увеличивает счётчик при
создании новой ссылки и уменьшает при её исчезновении (`del`, выход из области
видимости, переприсваивание). Как только счётчик становится равен нулю, объект
уничтожается **сразу же**, прямо в этой точке выполнения. Делает это сама машинерия
подсчёта ссылок — отдельный «сборщик» здесь не участвует. Так освобождается
подавляющее большинство объектов.

```python
import sys

a = [1, 2, 3]
b = a                      # на список ссылаются a и b
print(sys.getrefcount(a))  # ~3 (a, b и временная ссылка внутри getrefcount)

b = None                   # осталась одна ссылка — a
a = None                   # счётчик стал 0 -> список удаляется немедленно
```

**2. Сборщик мусора для циклов — вспомогательный механизм.**
У подсчёта ссылок есть слепое пятно — **циклические ссылки**. Если объекты ссылаются
друг на друга, их счётчики никогда не станут нулевыми, даже когда снаружи на них никто
не ссылается, и одним подсчётом ссылок такую группу не освободить.

Поэтому поверх подсчёта ссылок работает отдельный периодический проход — сборщик мусора для циклов.
Он просматривает объекты-контейнеры (списки, словари, экземпляры классов и т. п.; простые
`int` и `str` он не отслеживает), находит группы, достижимые только по внутренним ссылкам
цикла, и удаляет их. Он **не** «ждёт нулевого счётчика» — он занимается ровно теми
объектами, у которых счётчик остаётся положительным из-за цикла.

```python
a = {}
b = {}
a["ref"] = b   # a ссылается на b
b["ref"] = a   # b ссылается на a  -> цикл

del a
del b          # внешних имён нет, но счётчики не нулевые (a и b держат друг друга);
               # эту пару освободит уже сборщик мусора, а не подсчёт ссылок
```

### Плюсы и минусы

**Плюсы:** меньше ошибок работы с памятью, быстрее разработка, проще код.

**Минусы:** меньше контроля; сборка мусора тратит процессорное время и может
вызывать кратковременные паузы; память освобождается не всегда мгновенно.
