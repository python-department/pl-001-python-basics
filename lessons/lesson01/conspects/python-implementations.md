# Реализации интерпретатора Python

> **Главная мысль.** «Python» — это *спецификация языка* (описание синтаксиса и правил).
> А то, что мы запускаем на компьютере, — это конкретная **реализация**: программа,
> которая умеет исполнять код на Python. Реализаций несколько, и они отличаются
> тем, как именно выполняют программу и на чём написаны.

---

## Как Python вообще выполняет код

Классическая схема (на примере CPython):

1. **Исходный код** (`.py`) — то, что пишет программист.
2. **Компиляция в байт-код** — исходник переводится в промежуточное представление
   (`.pyc`), не привязанное к конкретному процессору.
3. **Виртуальная машина (VM)** — читает байт-код по одной инструкции и выполняет.

То есть Python и компилируется (в байт-код), и интерпретируется (байт-код исполняет
виртуальная машина). Разные реализации меняют шаги 2–3: например, добавляют перевод
в машинный код «на лету».

---

## 1. CPython — эталонная реализация

**Что это.** Референсная (стандартная) реализация, написанная на языке **C**.
Именно её скачивают с python.org, и именно её имеют в виду по умолчанию,
когда говорят «Python».

**Как работает.** Компилирует код в байт-код и исполняет его в своей
виртуальной машине.

**Плюсы:**
- максимальная совместимость: все нововведения языка появляются здесь первыми;
- огромная экосистема готовых библиотек, в том числе на C (NumPy, pandas и т. д.);
- стабильность и предсказуемость.

**Минусы:**
- относительно медленное выполнение «чистого» Python-кода;
- **GIL** (Global Interpreter Lock) — блокировка, из-за которой в один момент
  времени Python-байт-код исполняет только один поток, что мешает многопоточным
  вычислениям.

**Когда использовать:** почти всегда. Это выбор по умолчанию.

Именно эту реализацию Python мы будем изучать на нашем курсе.

---

## 2. PyPy — быстрая реализация с JIT

**Что это.** Альтернативная реализация, написанная на **RPython** (ограниченное
подмножество Python).

**Как работает.** Использует **JIT-компиляцию** (Just-In-Time): во время выполнения
находит «горячие» участки кода (например, циклы, которые крутятся много раз) и
переводит их прямо в машинный код. Дальше они работают почти как в компилируемых
языках.

**Плюсы:**
- значительное ускорение (часто в несколько раз) на долгих вычислительных задачах
  на чистом Python;
- в остальном ведёт себя как обычный Python.

**Минусы:**
- медленный «прогрев»: на коротких скриптах выигрыша нет, JIT просто не успевает
  разогнаться;
- поддержка библиотек с C-расширениями хуже и медленнее, чем в CPython;
- новые версии языка догоняет с задержкой.

**Когда использовать:** долго работающие программы с тяжёлыми вычислениями на
чистом Python, где важна скорость.

---

## 3. Jython — Python на JVM

**Что это.** Реализация Python поверх **Java Virtual Machine (JVM)**.

**Как работает.** Компилирует Python-код в байт-код Java, который исполняет JVM.

**Плюсы:**
- прямой доступ к любым Java-библиотекам из Python-кода;
- удобно встраивать скрипты в Java-приложения;
- нет GIL.

**Минусы:**
- развитие сильно отстаёт: долгое время не было поддержки Python 3;
- нельзя использовать библиотеки с C-расширениями (NumPy и подобные).

**Когда использовать:** нужно совмещать Python с экосистемой Java.

---

## 4. IronPython — Python на .NET

**Что это.** Реализация Python для платформы **.NET**.

**Как работает.** Компилирует Python-код в байт-код .NET (CLR).

**Плюсы:**
- доступ к библиотекам экосистемы .NET и языку C#;
- нет GIL.

**Минусы:**
- поддержка новых версий языка отстаёт;
- ограниченная совместимость с C-расширениями.

**Когда использовать:** интеграция Python в приложения на .NET.

---

## Сравнительная таблица

| Реализация | На чём написана | Платформа / особенность | Главный плюс |
|---|---|---|---|
| **CPython** | C | эталон, байт-код + VM | совместимость, экосистема |
| **PyPy** | RPython | JIT-компиляция | скорость на чистом Python |
| **Jython** | Java | работает на JVM | доступ к Java-библиотекам |
| **IronPython** | C# | работает на .NET | доступ к .NET-библиотекам |

---

## Вывод

- **Спецификация языка одна, реализаций много.** Они по-разному исполняют один и
  тот же код на Python.
- **CPython** — стандарт де-факто и выбор по умолчанию.
- Остальные реализации решают частные задачи: **PyPy** — скорость,
  **Jython / IronPython** — интеграция с JVM и .NET.
- Выбор альтернативы оправдан, только когда её преимущество действительно нужно;
  во всех прочих случаях берут CPython.
