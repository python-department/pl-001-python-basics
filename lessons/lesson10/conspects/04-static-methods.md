# Функции в пространстве имен класса: staticmethod

> **Главная мысль.** Функция, определенная в теле класса, становится
> атрибутом объекта класса, то есть размещается в его пространстве имен.
> Благодаря этому логически связанные функции можно сгруппировать под именем
> класса и не перегружать пространство имен модуля. Если функции не требуется
> доступ ни к состоянию класса, ни к состоянию экземпляра, ее оформляют как
> **статический метод (static method)** с помощью декоратора `@staticmethod`.
> Статический метод вызывается через имя класса и не получает неявных
> аргументов.

---

## 1. Функция как атрибут класса

Инструкция `def` в теле класса создает обычный объект-функцию и связывает его
с именем в пространстве имен класса. Это такое же присваивание, как и любое
другое в теле класса, поэтому функция становится **атрибутом** объекта класса и
доступна через точку:

```python
class Greeter:
    def say_hello(name: str) -> str:
        return f"Hello, {name}!"


print(Greeter.say_hello("Alice"))  # Hello, Alice!
```

Функция вызывается как атрибут: сначала через `Greeter.say_hello` по имени
находится функция, затем она вызывается с переданными аргументами.

Каждый класс имеет собственное пространство имен, независимое от
пространства имен модуля и от пространств имен других классов. Внутри одного
пространства имена уникальны, как ключи словаря, но в разных классах могут
существовать одинаковые имена: они не конфликтуют друг с другом.

---

## 2. Мотивация: группировка функций по смыслу

В больших программах много функций, и их имена в пространстве имен модуля
могут конфликтовать. Предположим, что нужно проверять корректность адреса
электронной почты и номера телефона. Если оформить проверки обычными
функциями, придется придумывать для них разные имена и добавлять префиксы:

```python
def is_valid_email(address: str) -> bool:
    return "@" in address


def is_valid_phone(number: str) -> bool:
    return number.isdigit()
```

Альтернатива — собрать функции в пространствах имен классов, названных по
смыслу, и дать им короткие одинаковые имена:

```python
class Email:
    def is_valid(address: str) -> bool:
        return "@" in address


class Phone:
    def is_valid(number: str) -> bool:
        return number.isdigit()


print(Email.is_valid("alice@example.com"))  # True
print(Phone.is_valid("12345"))              # True
print(Phone.is_valid("12a45"))              # False
```

Теперь принадлежность функции видна по записи вызова: `Email.is_valid` и
`Phone.is_valid` — разные функции с одним именем в разных пространствах имен.
Класс в этом случае используется как **пространство имен для группы
связанных функций**.

## 3. Декоратор staticmethod

Функция внутри класса, которая в своей работе не обращается ни к самому
классу, ни к его экземплярам, называется **статическим методом**. Такую
функцию оформляют декоратором `@staticmethod`:

```python
class Temperature:
    @staticmethod
    def celsius_to_fahrenheit(celsius: float) -> float:
        return celsius * 9 / 5 + 32

    @staticmethod
    def fahrenheit_to_celsius(fahrenheit: float) -> float:
        return (fahrenheit - 32) * 5 / 9


print(Temperature.celsius_to_fahrenheit(100))  # 212.0
print(Temperature.fahrenheit_to_celsius(212))  # 100.0
```

Декоратор делает две вещи:

1. **Фиксирует назначение функции.** Читатель кода сразу видит, что функция
   не использует ни состояние класса, ни состояние экземпляра и ее результат
   зависит только от переданных аргументов.
2. **Отключает передачу неявных аргументов.** При вызове функции из
   пространства имен класса через экземпляр Python неявно передает экземпляр
   в качестве первого аргумента. Обычная функция на это не рассчитана: ее
   первый параметр получил бы экземпляр вместо переданного значения, а
   количество аргументов оказалось бы на один больше ожидаемого, что приводит
   к ошибке `TypeError`. Декоратор `@staticmethod` отменяет такую подстановку:
   параметры получают только те значения, которые передал вызывающий код, при
   любом способе вызова. Подробно это рассмотрено в разделе 4 конспекта
   [«Методы экземпляров: self и __init__»](07-instance-methods.md).

При вызове через имя класса обычная функция из раздела 1 и статический метод
ведут себя одинаково. Декоратор `@staticmethod` принято применять всегда, когда
функция является частью интерфейса класса, поскольку он явно показывает
намерение автора: перед нами статический метод, а не случайная функция.

---

## 4. Ограничения статических методов

Статический метод не получает ссылку на класс, поэтому, как и любая функция в
теле класса, он не видит имен из пространства имен класса напрямую. Если нужно
обратиться к другому атрибуту класса, придется указать имя класса явно:

```python
class Temperature:
    freezing_point = 32

    @staticmethod
    def celsius_to_fahrenheit(celsius: float) -> float:
        return celsius * 9 / 5 + Temperature.freezing_point

    @staticmethod
    def describe(celsius: float) -> str:
        return f"{celsius} C = {Temperature.celsius_to_fahrenheit(celsius)} F"


print(Temperature.describe(100))  # 100 C = 212.0 F
```

Такой код работает, но имеет недостаток: имя класса записано внутри методов, и
при его переименовании придется менять все методы. Если функции
действительно требуется обращаться к атрибутам или методам класса, лучше
использовать не статический метод, а **метод класса**, который получает объект
класса автоматически. Он рассматривается в следующем конспекте.

## Вывод

- Функция, определенная в теле класса, становится атрибутом объекта класса и
  вызывается через точку: `ClassName.function(...)`.
- Размещение функций в пространстве имен класса позволяет группировать их по
  смыслу и использовать короткие одинаковые имена в разных классах без
  конфликтов.
- **Статический метод** — функция в теле класса, оформленная декоратором
  `@staticmethod`. Она не получает неявных аргументов и не зависит от
  состояния класса и экземпляров.
- При вызове через класс статический метод ведет себя так же, как обычная
  функция. Декоратор нужен для вызова через экземпляр: он отключает неявную
  передачу экземпляра первым аргументом. Кроме того, он показывает читателю,
  что функция не использует состояние класса.
- Внутри статического метода атрибуты класса доступны только через имя
  класса. Если они нужны методу, лучше сделать его методом класса.
